## 三层证据（喉咙不存在）

1. **nii.gz 标签层**：口咽标签触扫描下面 **29/29**（gap 恒 = ½ z 体素，bbox 中心约定的地板值）；下咽 **28/29 = 0 体素**，唯一非零 b01 = 255 体素 = **38.0 mm³** 底部 3 层 stub（贴下面 97 体素，air_fraction 0.91，噪点/边界 stub 级，不构成可用下咽）。
2. **原始 DICOM 层**：b01–b24 文件数（195/173/154/…/145）与 nii.gz z 层**逐例吻合**（无 Z 裁剪）；p0 三部 132+132+131=395 文件铺满 394 层，无隐藏段。
3. **序列层**：case25/26/27（=p1/p3+p3t1/p2）**全部**序列（含 3D_Sinus\*/3D_AB\*/CH/CH_4/MPR）z 范围在鼻窦扫描内或**上方**，无一条向喉侧延伸（例：CH z 291.77→431.9 在 p3 扫描 281.29→392.29 上方）。

## 坑与修复（留痕）

- **nibabel 轴序第 N 次踩坑（连踩两次）**：nibabel 数组是 `(x,y,z)`，SimpleITK `GetArrayFromImage` 是 `(z,y,x)`。首版审计全按 SimpleITK 习惯写 → z 向结论全错（曾输出 "oro_gap_inf=129mm/trunc=False" 假象）；剖面脚本首版塌错轴 → IndexError。修正后**先用 T-032 已知答案验证**（p0：148837 体素 / z 0–107 / gap 0.175=0.35/2 逐位吻合）再采信。
- **命名反转**：剖面脚本首版 `top=zz.min()` 实为**下端** → 派生字段名全反，曾误导出「到扫描底部仍宽 107–257」的误读。已重写（inferior/superior 语义）并重生成 JSON；旧文件被取代不保留。
- **HU-only 全层截面不可用作气道量**：含腔外空气（b01 达 45918 mm²）→ 必须 标签∩HU。该中间产物弃用未入库。
- **ITK nifti 写盘不认中文路径**（Windows fopen 非 UTF-8）→ 一律 ASCII 暂存 `C:/ts_work/` 再复制回写域。

## 结论

1. 分割位置方向**没有错**（29/29 C0–C4 全过）——「整到真正正确的位置」在位置层面无事可修。
2. 真正缺的是**扫描覆盖**：口咽以下在任何数据中不存在（三层证据闭环）。分割不可能造出喉咙——这不是分割的失败，是数据的边界。
3. 「分割没有价值」**一半对一半言过其实**：对——全喉链目标在当前数据不可达；言过其实——鼻+鼻咽域完整且是 ENS 病理与主诉所在，b15 Δp 10.286 Pa / R 0.0411 / WSS 1.102e-3 N（T-042 VERIFIED）全部成立；当前鼻咽出口监测量（Q=15 L/min、A=487.7mm²、ū=0.513 m/s、p=0 gauge）就是未来喉模型的**喉部入口边界条件**，现在就能给。
4. 数据内最优 = 纳入可见口咽 → **T-047 已执行**（b01 扩展域 auto_pass，出口=工程截断 148.93mm²）。
