1. **第四标签名 = `oropharynx`**，且 **24 例（`b01..b24`）masks 目录全部存在且非空**
   （体素 6748–54370，实测 `C:/ts_work/bXX/masks/oropharynx.nii.gz`）——无缺失，可行性成立。
2. **生产链与 T-054 扩展域脚本同源**：都走 `export_candidate_preview.mask_surface`
   （marching cubes → LPS affine）+ `UNION ∩ HU<-300`。差异**只有 `ROI_LABELS` 一项**
   → 不需要换表面构建方式，改常量即可（成本低）。
3. **不需重跑分割**：`C:/ts_work/bXX/masks/` 已含全部标签，本卡只重跑 stage 3(表面) + stage 5(开口)。
4. **T-054 已解决出口口径且原理正确**，本卡直接沿用（杜绝自行拍定）：
   - 开口名 `oropharynx_truncation_outlet`
   - 平面 = 扩展气域 mask **最底体素中心平面上方 0.5 mm** 轴向切割，法向 `[0,0,1]`，`keep_positive`
   - `CAP_TARGET = 10 mm²` 是 **floor 不是生理目标** → 自然截断面积（b01 ≈139 / b15 ≈113 mm²）远在其上，
     **二分永不触发，平面停在锚点 = 最大域**
   - `AREA_BAND = [10, 600]` **只记录、不做解剖验证**（截断出口面积由扫描 FOV 决定，是工程属性，
     卡它是把工程属性当解剖属性验——旧带 [120,500] 会让 b15(112.51) 直接 escalate）
5. **必须默认 `allow_onset_outlier=True`**：扩展表面上鼻孔 onset 扫描射线会穿过新加的口咽管
   （~20 mm 下方）→ 报告假 onset（b01 实测 −19.5/−20.0 mm）。这是**每个病例必然出现**的，
   不是偶发，故不能保留为 opt-in。
