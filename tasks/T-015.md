## 输入输出与接口
- 输入：当前病例/审核记录、既有 CFD 契约和实际本机环境；非患者算例沿用 `solver_reference/run_reference.py`，WSL 工作目录必须 native Linux 且每任务隔离。
- GET `/api/simulation/catalog`：`schema: nasal_simulation_catalog/v1`，`cases` 数组。每例含 `id,label,kind,run_allowed,blocking_reasons,geometry_status,mesh_status,solver_status,artifacts`；kind 为 patient 或 reference。
- GET `/api/simulation/jobs`：`jobs` 数组；POST 同路径仅接受 `case_id,action,settings`。action 为 `preflight` 或 `run_reference`；参考 case_id 为 `reference_channel`。
- GET `/api/simulation/jobs/<job_id>`：状态、阶段、日志摘录、结果摘要及产物 URL；持久化 `job.json`，服务重启仍能读到实际状态。
- `/simulation-assets/<job_id>/<name>` 只服务显式结果资产；不可访问任意路径或原始 CT。
- preflight 返回真实来源和未满足项；无证据时不能填 passed、0 或成功结果。患者运行在现有准入未满足时必须拒绝并给具体原因。
- run_reference 必须启动实际既有求解脚本，不得以解析解、旧报告或 synthetic response 代替新算例；全局 CPU 锁复用 CT execution_lock，进程完成即落盘原始退出码和错误。

## 验收
1. 任务生命周期、重启读取、异常、跨域/路径边界及患者拒绝有定向测试。
2. 同一时间只一个 CPU 工作；不覆盖既有 benchmark；Linux 目录隔离，后台进程落盘。
3. 只读环境探测与 catalog 可实际调用，参考结果和患者预览身份分明。
4. 不宣称真实运行已通过；Lead 通过 HTTP 启动新参考任务、读取结果并 fresh 独立复验。
5. 输出执行说明与结论卡；只 add 自身精确路径，提交 `[T-015]`。VERIFIED/CLOSED 由 Lead 授予。
