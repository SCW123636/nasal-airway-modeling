## 0. 一句话结论（给主对话）

`Face interpolation weight < 0.05` 是 checkMesh 对**面插值几何权重**的告警：它测的是"某个面的插值点是否过分偏向一侧相邻单元"（该侧贡献权重 <0.05 即告警）。**它不会让 simpleFoam 直接崩溃**（只是线性组合，且带 VSMALL 保护），但它与本案并存的 204 个 >70° 非正交面、585 个 determinant<0.001 单元高度同源——都是同一批网格畸变区的症状。**真正的处置在网格侧（修复/光滑），求解器侧用 `limited`/`corrected` + 提高 `nNonOrthogonalCorrectors` 只是缓解，不是根治**。T-004 若崩，先看 residual 是否在低权面聚集区发散，再回头做网格修复。

## 1. 判据语义（源码）

### 1.1 调用入口与阈值来源

`checkMesh -allGeometry` 在 `checkGeometry.C` 中调用（注意：**阈值 0.05 是调用处硬编码传入，不是 checkFaceWeights 内部常量**）：

- `applications/utilities/mesh/manipulation/checkMesh/checkGeometry.C:904-905`
  ```cpp
  faceSet faces(mesh, "lowWeightFaces", mesh.nFaces()/100);
  if (mesh.checkFaceWeight(true, 0.05, &faces))   // ← 0.05 在此硬编码
  ```
- 同块并列的 `Face volume ratio` 检查阈值 0.01 同样是硬编码（`checkGeometry.C:926` `mesh.checkVolRatio(true, 0.01, &faces)`）。

【源码】判据的"0.05"由 checkMesh 的 `checkGeometry()` 包装决定，用户不能在 `-allGeometry` 模式下通过字典改它（与 determinant / skewness 等由 `meshQualityDict` 控制的阈值不同——本例中 determinant 阈值 0.001 来自字典，而 weight/volRatio 是代码常量）。

### 1.2 权重定义式（min 的几何含义）

核心计算在 `polyMeshGeometry.C:1135-1280` 的 `checkFaceWeights`：

- 对内表面（`polyMeshGeometry.C:1173-1178`）：
  ```cpp
  scalar dOwn = mag(fa & (fc - cellCentres[own[facei]]));   // 点积取模
  scalar dNei = mag(fa & (cellCentres[nei[facei]] - fc));   // 点积取模
  scalar weight = min(dNei, dOwn) / (dNei + dOwn + VSMALL); // 定义式
  if (weight < warnWeight) { ... 记入选集 ... }
  ```
  其中 `fa`=面法向面积矢量，`fc`=面心，`cellCentres[own/nei]`=两侧体心。

【源码】`dOwn`、`dNei` 是"体心—面心"矢量在**面法向**上的投影长度模（因 `fa` 含面积，分子=面积×投影距离，但分子分母同乘面积，故 `weight` 与面积无关，纯为两投影距离之比）。

【源码】`weight = min(dNei, dOwn)/(dNei+dOwn)` 即**两个几何插值权重中较小的一个**。OpenFOAM `gauss`/`linear` 插值的几何权重为 `w_own = dNei/(dNei+dOwn)`、`w_nei = dOwn/(dNei+dOwn)`（见 1.4 备注），故被检查的 `weight = min(w_own, w_nei)`。它的取值范围 (0, 0.5]：等于 0.5 表示面心恰好落在两体心连线中点（最优），趋向 0 表示面心极靠近某一侧体心（插值点几乎贴着那个单元）。

- `minWeight` 初值为 `GREAT`，在循环中对每个被检面取 `min(minWeight, weight)`（`polyMeshGeometry.C:1195` 内表面、`1221` 耦合面、`1254` baffle），再 `reduce(minWeight, minOp)`（`1257`）得到**全局最小权重**。`if (minWeight < warnWeight)` 返回 `true`（`1260-1271`），即 checkMesh 报 `Failed` 的那一项。

【源码】日志里打印的 "Face interpolation weight : minimum: 0.01178 ..."（`checkMesh.log:105`）是该全局最小值，由 `checkFaceWeights` 直接算出，与被记入选集的面数无关。

### 1.3 与 "Face volume ratio" 检查的关系

两者都是 `allGeometry` 下的**并列面级检查**，互不嵌套，但都指向局部网格畸变：

| 检查 | 文件:行号 | 定义式 | 阈值（硬编码） | 含义 |
|---|---|---|---|---|
| Face interpolation weight | `polyMeshGeometry.C:1178` | `min(dNei,dOwn)/(dNei+dOwn)` | 0.05 (`checkGeometry.C:905`) | 面心相对两侧体心的**位置偏置**（几何插值权重偏小） |
| Face volume ratio | `polyMeshGeometry.C:1336` | `min(ownVol,neiVol)/max(ownVol,neiVol)` | 0.01 (`checkGeometry.C:926`) | 相邻两单元**体积悬殊** |

【源码】二者算法独立：`checkFaceWeights` 用"体心—面心在法向上的投影距离之比"，`checkVolRatio` 用"相邻单元体积之比"。一个面可以只触发其一，也可以两者都触发（当"面贴着一侧小单元"时，体积比往往也小）。**不能从一个推出另一个**。本案日志（`checkMesh.log:108`）`Face volume ratio` min=0.0119，刚好压在 0.01 阈值之上 → "check OK"，说明本批问题以"低权重"为主，"体积比"基本过关（二者非同因的强证据）。

### 1.4 备注：权重与 surfaceInterpolation 的关系

【推断/文档】OpenFOAM 的 `surfaceInterpolation::weights()` 计算几何权重 `w = |Sf & (Cf - Cn)| / |Sf & (C0 - C1)|`（owner 侧），与 1.2 的 `dNei/(dNei+dOwn)` 数学上同一量，是 `gauss`/`linear` 插值 `div`/`laplacian` 项的通量权重来源。**但本解压树只含 `OpenFOAM` 与 `dynamicMesh` 两模块，`finiteVolume` 不在**，故无法在此逐行引用 `surfaceInterpolation.C`。该等式按 OpenFOAM 通用机制标注为【推断】，未作为源码事实引用。

## 2. 成因机制（区分【源码支持】与【推断】）

### 2.1 几何成因（从定义式直接推出）

【源码】由 1.2 的定义式，`weight → 0` 当且仅当 `min(dNei, dOwn) → 0`，即**面心沿法向到某一侧体心的投影距离趋于 0**——面心几乎贴在某一相邻单元体心附近。对应几何情形：

1. **某一侧单元在面法向方向上极"薄"**（sliver / 近退化单元）：体心离共有面很近，dOwn 或 dNei 很小。
2. **面心与体心连线严重偏离法向（高 skewness）**：此时 `fa & (fc - Cown)` 的投影被"吃掉"，即使欧氏距离不小，投影距离也小 → 权重偏小。注意定义式用的是点积（投影）而非欧氏距离，所以单纯"skew"就会拉低权重，不必几何上真的薄。
3. **两体心与面心近似共线且一侧极近**：collapsed 拓扑。

【源码支持】以上三点均直接来自 `dOwn = mag(fa & (fc - Cown))` 的投影语义，是定义式成立的几何推论，不依赖外部假设。

### 2.2 与各候选成因的关系（哪些有据、哪些推断）

- **极端非正交 / skew**：【推断】本案 `checkMesh.log:90-91` 报 "Max non-orthogonality 87.3°、204 个 >70° 严重非正交面"，`Max skewness 1.63 OK`。非正交与 skew 是低权重的**强相关因素**（见 2.1 点 2），但本批低权面（114）与严重非正交面（204）并非同一集合——是否重叠需 face→cell 拓扑（见第 4 节，当前不可得），故只能定性说"同源于同一批畸变区"，不能断言二者集合相等。
- **与 585 个 determinant<0.001 单元同源**：【推断为主】determinant 衡量单元形状良态性（体心/面心/顶点构成的金字塔体积），低权重衡量面两侧体心投影失衡；二者都是"网格畸变"的不同投影。低权面**大概率**贴在 585 个差单元之一的邻面，但**本调研无法用现有产物证明**（缺少 face→owner/neighbour 拓扑，见第 4 节）。
- **sliver 邻域**：【推断】maxh=0.4 未修复时仅 22 个低权面，修复后反而升到 106 个；maxh=1.0 修复后 114 个——**修复使低权面增多**，这与"修复动作（netgen 修复/merge）在局部制造了贴面薄层"的推断一致，但属推断，需 T-003 的 repair 日志交叉验证。

### 2.3 阈值 0.05 的物理尺度

【源码】0.05 表示：较小一侧的投影距离只占两侧投影总距离的 5%，即插值点偏离几何中心约 45%（几何权重 0.05 vs 0.95）。这属于"明显偏置但未必致命"的区间——远低于 skewness/非正交的"severe"量级，是质量告警而非合法性错误。

## 3. 对 simpleFoam 稳定性的影响与处置

### 3.1 会不会让 simpleFoam 崩？

【源码支持】`checkFaceWeights` 仅返回 `bool` 并（可选地）把面写入 set（`polyMeshGeometry.C:1260-1271`），**不抛 FatalError、不中止**。OpenFOAM 在 checkMesh 报此项 Failed 时仍照常求解。因此**低插值权重本身不是崩溃的直接原因**。

【推断/文档】真正的风险是**间接**的：
- 几何权重是 `gauss`/`linear` 通量插值的核心（`div(p,U)`、`laplacian(nuEff,U)` 等都依赖它）。权重趋 0 → 该面通量几乎由单侧单元决定，**插值精度下降**、对非正交/ skew 的修正项被放大。
- 当低权面与本案并存的 204 个 >70° 非正交面、585 个 determinant<0.001 单元**空间重叠**时，修正项与非正交修正（`nNonOrthogonalCorrectors`）可能放大局部误差，导致该区域 residual 难收敛甚至发散——但这是"难收敛/发散"而非"程序崩溃/除零"。VSMALL 在 `checkFaceWeights` 的分母已做保护（`polyMeshGeometry.C:1178`），插值本身不会除零。
- **定性排序（推断）**：对本例而言，**585 个 determinant<0.001 单元比 114 个低权面更可能直接危及稳定性**——determinant 极小意味着单元金字塔/体积计算病态，可能使离散算子在局部不定，比单纯插值偏置更"硬"。低权面是同一畸变区的软症状。

### 3.2 公认的处置手段（区分【文档/源码支持】与【社区常见做法】）

#### 3.2.1 网格侧（【文档/社区公认】根治手段）

- 低权重是几何症状，**根治在网格**：修复/光滑使面心回到两体心之间。`snappyHexMesh` 的 `meshQualityControls` 可设 `minWeight = 0.05`（或更高）作为生成约束；netgen/gmsh 的修复（本案已做，但见 2.2 修复反而增多——需 T-003 复验修复动作本身是否引入薄层）。
- 本案证据：maxh 从 1.0 收紧到 0.4 再修复，低权面从 114→106（略降），min weight 维持 0.0118——说明**仅靠现有修复未消除最差面**，可能需要针对性局部重剖分或 `renumberMesh`/`checkMesh -meshQuality` 引导的局部加密。

#### 3.2.2 求解器侧（【社区常见做法】缓解，非根治；finiteVolume 不在本树，未逐行核）

- `system/fvSchemes` 的 `div` 项用 `Gauss linear corrected` 或 `Gauss linear limited <coeff>`（如 `limited 1.0` / `limited 0.5`）替代裸 `Gauss linear`，对偏置/非正交更稳健。`limited` 用梯度限制器抑制越界，`corrected` 启用非正交修正。
- `system/fvSolution` 提高 `nNonOrthogonalCorrectors`（如 1→2 或 3）与 `nSweeps`，对非正交/偏置区做更多修正迭代；对含限制器的格式可加 `nLimiterIter`。
- 若局部发散，可用 `fvOptions`/局部 `relaxationFactors` 或对该区域单独加 under-relaxation。
- **注意**：这些只缓解，不消除几何缺陷；若最差面 weight=0.0118（权重比约 1:85），修正项可能被放大到危险程度，最终仍需网格侧处理。

#### 3.2.3 监控信号（给 T-004）

- T-004 若发散，**先看 residual/initial 几步是否在特定区域（鼻腔狭窄、转弯处）突然抬升**——低权面常聚集在几何突变处。
- 用 `checkMesh` 输出的 `lowWeightFaces` set 反查 T-004 算例中 `U`/`p` 残差是否在这些面附近异常（需在 case 的 `constant/polyMesh/sets` 放同一 set 文件，本调研的 `b15_lowWeightFaces.set` 即 maxh=1.0 修复版的那 114 面）。
- 若 T-004 改用 maxh=0.4 修复网格，则对应低权面是 106 个（非本 set 文件的 114 个）。

## 4. 与 585 个 flagged 单元的关系（集合交叠分析）

### 4.1 输入与可证事实

- `C:\ts_work\mesh_tools\patient_mesh_20261013\b15_lowWeightFaces.set` → **faceSet，114 个面**，标签区间 [21900, 2256591]。【源码/工具】纯 Python 解析确认计数与声明一致（末位 `(...)` 块内整数 114 个）。
- `C:\ts_work\mesh_tools\patient_mesh_20261013\b15_underdeterminedCells.set` → **cellSet，585 个单元**，标签区间 [1077, 1133228]。【源码/工具】同上，585 个。
- 二者 `.set` 文件头 `location "constant/polyMesh/sets"`、`object` 名与 `checkMesh.log` 输出一致 → 这两个 set 来自 **maxh=1.0 修复网格**（114 面/585 单元，与 `checkMesh.log:106,102` 完全吻合）。

### 4.2 直接整数交叠无意义（拓扑不同类）

【源码/工具】`lowWeightFaces` 是 `faceSet`（面索引空间），`underdeterminedCells` 是 `cellSet`（单元索引空间）。OpenFOAM 中 face 与 cell 各有独立编号，两套数字处于**不同索引域**。把 114 个面号与 585 个单元号直接做集合交集，结果在数学上无网格拓扑意义——**本报告不给出"重叠 N 个"这种误导数字**。

### 4.3 邻接判定需要但缺失的输入

要回答"114 个低权面是否落在 585 个 flagged 单元邻域"，必须知道 **每个面的 owner/neighbour 单元**（即 `constant/polyMesh/owner` 与 `neighbour` 文件），把每个低权面映射到其两侧单元，再测这些单元是否在 585 集合中。

【工具/实测】我在 `patient_mesh_20261013` 全树搜索 `owner`/`neighbour`/`faces`/`cells` 等 polyMesh 拓扑文件（`find -iname`），**未找到任何 OpenFOAM polyMesh 拓扑文件**；`foam_b15_*` 与 `t001b_maxh04/foam_foam_*` 目录仅含日志与 case dict，不含转换后的 polyMesh。`b15_patient_maxh1.arrays.npz`（28MB）虽可能含四面体连接，但：
(a) 本机 `python3` 无 `numpy`，无法直接读；
(b) 即便可读，从 tet 数组重建 face→owner/neighbour 邻接超出"轻量 Python 集合运算"范围，且缺少确切 schema 易错。

### 4.4 结论（诚实边界）

- 【可证】114 低权面 与 585 差单元 是**不同拓扑实体**；直接交叠无意义；两 set 均来自 maxh=1.0 修复网格。
- 【不可做】在现有产物下**无法**完成"面→单元邻域交叠"分析。缺的是该网格的 `constant/polyMesh/owner`+`neighbour`（或含 face→cell 邻接的等价数据）。
- 【建议给 T-003/T-004】若需此交叠数，最轻量路径：在 maxh=1.0 修复网格的 case 目录读取 `constant/polyMesh/owner` 与 `neighbour`（纯文本），用几行 Python 把 114 个面号映射到单元号、与 585 set 求交即可（仍是"读文本 + 轻量集合运算"，符合零 CPU 约束）。本调研不臆造该结果。
