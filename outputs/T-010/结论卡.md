## 3. 风险清单

- **R1【已解释】暖跑 manifest 墙钟 8.9h vs 步骤 0.856s**：`run_status.json`（started_at 16:21:33Z / updated_at 01:15:44Z）+ `log.checkMesh` mtime 今晨 09:15 共同证明进程 00:21:33 启动后随会话中断被挂起、今晨恢复完成；步骤计时与 exit 0 不受影响，冷跑对照同时段干净完成。残留不确定：挂起机制（SIGSTOP vs 运行时停止）无法完全确证，但两种机制都不影响步骤级计时有效性。
- **R2** 暖跑 checkMesh（0.856s）比冷跑（0.485s）慢 1.8×——单样本噪声量级，未复测；矩阵成本核算以冷跑值为基线。
- **R3【排查后关闭】缓存签名覆盖面**：签名 = 网格字典（blockMeshDict / snappyHexMeshDict / fvSchemes / fvSolution / controlDict）+ triSurface STL 内容 + OpenFOAM 后端身份；复用路径（`inspect_reuse`→`_check_manifest_files`→`_mesh_files`）**重算已缓存 polyMesh 实际哈希与 manifest 比对**，外加 log.checkMesh 哈希与 Mesh OK 证据——手动损坏/触碰已缓存 polyMesh 会被发现并重建。此条为排查后关闭的假设风险，记录以备查。
- **R4** 签名不含 0/ 初始场与 transportProperties / turbulenceProperties——三者不参与网格生成，对网格正确性无影响；若未来网格步骤依赖新增文件类型，需同步扩展签名面。

## 5. 新发现风险 / 接线 bug（只记录不修）

1. **后台进程比子代理更韧**：暖跑进程跨会话挂起 8.9h 后自行完成并写盘——与「运行中的子代理活不过会话终止」并存的事实是「已启动的 OS 进程可以（挂起后恢复）」。矩阵长跑需以步骤级计时为准；`run_status.json` 的 started_at / updated_at 可作挂起取证。
2. **checkMesh 的 concave cells 检查对精化过渡结构敏感**：圆管 refine 1 1 即 784 个，refine 2 2 达 91315（随精化增多，系精化过渡结构驱动）——与患者网格历史 sliver 问题同类，矩阵 maxh 档位选择应预判精化过渡代价。
3. **失效判据是输入签名（保守）而非输出比对**：S1c 附带发现改 maxGlobalCells（5000000→4000000）未改变实际网格（13 文件 sha 逐位同）但缓存仍正确失效。对矩阵的含义：改任何网格字典数值都触发重建，即使网格本不会变——保守方向正确，但排期时别指望「改了但网格没变」能省钱。
