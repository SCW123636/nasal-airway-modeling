# T-015 工作台 CFD 任务服务

## 实现范围
- 新增 `work/lib/cfd_workspace_jobs.py`；在既有 loopback HTTP 服务注册 catalog/jobs/job/显式结果资产接口。
- 独立 Windows Python 工作进程执行任务，`CASE_ROOT/simulation_jobs/s_<24hex>/job.json` 原子落盘；服务重启读取原任务，不自动重跑已完成任务。
- 参考计算复用原 `solver_reference/run_reference.py`，每任务 native Linux 目录为 `<WSL home>/nasal_cfd_workspace_jobs/<job_id>`；导出到该任务目录，原基准结果不被覆盖。
- 复用 `ct_case_pipeline.execution_lock(CASE_ROOT)`，参考任务与 CT 导入共享一个跨进程 CPU 锁；单个服务只允许一个 queued/running 参考任务，实际计算时锁跨服务生效。
- 子进程原始退出码、执行日志、环境预检、脚本 SHA256 和实际运行记录保留。无命令执行时 `exit_code` 保持 null。
- 完成后从同任务真实 `internal.vtu` 提取中面三角网格与 U/p 字段。核对 p 维度后使用同任务 rho 转为 Pa，坐标 m→mm，轴作刚性循环置换；不拉伸几何，不使用解析速度/压力数组填充字段。
- `numerical_validation=unchecked`、`clinical_validation=not_validated`，患者 CFD 仍未准入；本次单档参考不宣称完整三档网格验证。

## HTTP 契约
- `GET /api/simulation/catalog` → `{schema:"nasal_simulation_catalog/v1",cases:[...]}`。
- `GET /api/simulation/jobs` → `{jobs:[...]}`。
- `POST /api/simulation/jobs` 只接受 `case_id/action/settings`，返回 202 与 job 本体。`action=preflight|run_reference`。
- 参考 `case_id=reference_channel`；settings 只支持 `levels` 数组，元素为 coarse/medium/fine，默认 `["coarse"]`。不支持流量、压力覆盖；未知字段拒绝。
- 参考固定实际参数：bulk U=0.1 m/s、gap=2 mm、width=1 mm、length=40 mm、Q=2e-7 m³/s（0.012 L/min）、出口 gauge p=0 Pa、层流。
- `GET /api/simulation/jobs/<s_24hex>`：`status` 为 queued/running/completed/failed/interrupted；字段包括 stage、preflight、result、artifacts、log_excerpt、error、exit_code。
- preflight 本身执行完成可为 `status=completed`，其 `preflight.passed=false` 表示不准入；两者不能混同。
- `GET /simulation-assets/<s_24hex>/<name>` 只提供 job.json 中显式发布且仍在该任务目录内的资产；job.json、原始 CT 与任意路径不开放。
- 三维入口是 artifacts 中 name=viewer 的 URL：`/viewer/index.html?manifest=/simulation-assets/<s_24hex>/viewer.json`。
