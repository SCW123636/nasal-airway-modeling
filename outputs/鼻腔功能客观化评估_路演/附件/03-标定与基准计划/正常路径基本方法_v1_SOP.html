鼻腔 CFD 表面制备 — 正常路径基本方法（v1）

范围：正常状况。异常/特殊状况（p0 类点位异常、序列不可用、几何自相交等） 本文档不处理，另立文档。本方法的目标是让正常例无人值守跑通。

0. 什么叫「正常状况」

一条数据只有当下面 6 条全满足 时才适用本方法。任何一条不满足即转人工通道， 不在本文档范围内。

# 条件 判据
N1 有可用轴位原始序列 ImageType 含 ORIGINAL + AXIAL，in-plane ≤ 0.8 mm
N2 分割三标签非空 nasal_cavity_left/right、nasopharynx 体素数 > 0
N3 空气腔非空 三标签并集 ∩ HU < −300 后体素数 > 0
N4 表面闭合 marching cubes 后 boundary_edges == 0
N5 自动提案可用 三开口有可用 point_lps_mm + normal_lps；status 见 §0.1
N6 开口面积入带 鼻孔 ∈ [40,140] mm²、鼻咽出口 ∈ [120,500] mm²

27 例新数据中，24 例（b01–b24）满足 N1（单一干净序列）； b25/b26/b27 是多序列例，不属于本文档范围。

0.1 ⚠️ N5 的 needs_review 不是真正的阻塞（2026-10-12 定案）

未触边的两例 b01 / b11 恰好就是通过的那两例

0.2 onset_outlier 门降级为顾问标记（2026-10-13，opt-in）

背景：onset_outlier 把「开口截面总面积首次达 50 mm² 的位置落在带 [−4, +1] mm 之外」 当成硬阻塞。该带宽取自五例试点，它守的是以 onset 为锚的放置搜索。

为什么它已不再承重：2026-10-13 起搜索起点默认改为 reviewed（§2⑤）， onset 不驱动任何位置——它既不参与 base，也不参与二分窗口。

A/B 实测（work/lib/probe_onset_gate_bypass.py：同输入、同 --search-origin reviewed， 只切换 onset 门）：

例 门开（stock） 门关
b15 / b18 auto_pass 逐位相同（80.04/80.06/439.18；80.09/80.07/251.64）
b23 escalated onset_outlier auto_pass 87.97/80.45/276.87（全在带内；出口仅位移 +0.45 mm）
b04 escalated onset_outlier escalated seed_lost（nostril_L + 出口）← 真实失败理由

三条读数：① 门对 onset 在带内的例严格 no-op（elif 分支不进入，代码路径完全相同）； ② b23 被门挡住，但其 reviewed 锚点搜索能到带内面积；③ b04 去掉门后仍升级， 理由从 onset_outlier 换成真正起作用的 seed_lost。 → 该门在此批次从未提供安全性，只做「阻塞」与「误标」。

处置（opt-in，默认路径逐字未变）：新增 --allow-onset-outlier （auto_opening_pipeline.py / nasal_pipeline.py）。置位时越带 onset 记入报告 onset_flags（观测信息不丢），由放置自身门禁（seed_lost / clip_failed / gate_failed / 面积带）决定成败。no_onset（±30 mm 内找不到任何 ≥50 mm² 截面） 仍是硬阻塞——那是「无可用几何」，不是起始位置偏好，与本节结论无关。

为什么是 opt-in 而非改默认：2026-10-13 曾把「保留为硬阻塞」写成决定，理由是 「去掉它等于用未知换通过」。该理由对本批 b23 已被证伪（它不是「未知」，而是 可核验的带内放置）；但改变对外基准仍需用户裁定，故先提供开关并记录两条臂的数字。

1. 五步链路（标准流程）

① 选序列      batch27_series_choice.py    →  每例一个 DICOM 目录
② 分割        ts_nasal_seg.py --batch-dir →  ct.nii.gz + masks/*.nii.gz
③ 提案        auto_anatomy_landmarks.py   →  landmarks.json（自动解剖点位）
④ 建表面      batch27_surface.py          →  source_surface.vtp
⑤ 开口定位    auto_opening_pipeline.py    →  逐例报告 + auto_placed.vtp

单一入口：python nasal_pipeline.py --cases b01 b02 ...（见 §4 验收后可用）。

2. 各步判据与参数（全部已实测，非拟合）

② 分割

  • 任务 head_glands_cavities，CPU 约 136 s/例，只取三标签。
  • 阈值 −300（与试点管线一致）。−350/−400 属验证任务，不在本方法内静默改。

③ 提案

auto_anatomy_landmarks.py 产出的三点位 仅供作起点，不是临床结论。

④ 建表面

  • 三标签并集，再 ∩ HU < −300。 这一刀去掉 TotalSegmentator 在骨壁上纳入的部分容积体素；不做会明显更厚更糙。
  • MC 在体素空间做，再套完整 LPS 仿射（复用生产函数 mask_surface）。

⑤ 开口定位（v2 判据：按 cap 面积二分）

沿平面法向二分，直到生产 clip_and_cap 实际产出的端盖面积达到解剖目标：

开口 目标 成人参考
鼻孔 L / R 80 mm² 50–100
鼻咽出口 250 mm² 150–400
  • 三开口坐标下降，≤3 轮（实测第 2 轮即收敛，末轮位移 0.0 mm）。
  • 每开口 9 次二分；窗口按搜索起点分档：onset 14 mm / 2⁹ ≈ 0.027 mm， reviewed 3 mm / 2⁹ ≈ 0.006 mm。
  • 搜索起点默认 reviewed（2026-10-13 起）：从 landmark 阶段提出的平面 （= 解剖锚点，王湧瑞 25/25 accept）出发，只有该处 cap 不足目标时才位移。 onset 保留为对照臂（--search-origin onset）。

为什么默认起点从 onset 改成 reviewed（2026-10-13 实测）： onset 是 detect_onset 判据的副产物——「截面总面积首次达 50 mm²」的位置 （auto_opening_placement.py 的 AREA_ON = 50），而 cap 目标是 80/250，相差 5 倍。 ROI 盒随平面一起平移，盒沿法向的负侧储备实测只有 ~1.15 mm，于是任何 |onset| ≳ 1.25 mm 的开口在搜索起点处盒内零种子：

实测（b15 出口，push = 相对复核点位位移） seeds cap
0.00 mm 832 439.18（带内）
−1.00 mm 10 6.9
−1.25 mm 0 FAIL

onset 起点下 b05/b15/b18 全部 seed_lost；改 reviewed 起点后三例全部 auto_pass 且面积在带内（见 §5 表）。临界边界实测落在 push ∈ (−1.25, −1.00)： b16/b21（onset −1.25，push −0.75）在界内通过，b15（push −1.25）在界外失败， 两者只差 0.5 mm。

锚点超带的显式降级：若 reviewed 平面自身 cap 已超 band 上限（实测仅 b08： 出口 772.35 > 500），则回退 onset 起点并在报告写 origin_downgrade （含 reason 与违规面积），不静默换起点。b08 降级后 254.71，与 onset 基线逐位相同。

为什么不直接用 onset： v1 以「截面总面积」为被控量，该量有偏——p1 鼻孔处端盖面积 85.95 mm² 竟大于整张截面 70.4 mm²，数学上不可能。v2 改用生产 cap 面积，绕开该问题。

⚠️ 勘误（2026-10-12）

本表此前误记为「p2 出口 292.13 / p1 鼻孔 85.95」。这两个数字不属于 v2 管线， 它们是 ROI-box / 选择谓词时代（connectivity_opened_20261011）的固定平面面积—— 那个时代不做面积目标二分，p2 出口恰好落在 292.13。

v2 改按 cap 目标二分后，p2 出口 = 441.87、p1 鼻孔 = 80.07。 差异不是回归：source_sha256 与原始 v2 产物逐位相同，实为我把两条不同管线的数 混记成了一条基准。

教训：基准值必须带出处（文件路径 + 管线名），否则跨管线改名后就会 拿旧管线的数去验新管线，得出假失败。

缘由：本项目已多次出现「判据/解析代码自身坏掉但输出看起来合法」 （自相交 det 阈值、refine 写 area>=0、DICOM ImageType 索引猜错、 基准值跨管线混记）。任何新判据落地，先用已知答案验一遍，且已知答案要带出处。
