# 鼻腔—咽部扩展：范围、证据与后续验收

日期：2026-10-15。来源：用户确认按推荐推进咽部扩展；工程执行T-026，独立复核T-027（待建卡/派发）。

## 已授权方向

目标是使鼻腔下游的咽部气道进入可核查的患者建模流程。当前先完成现有影像入口和一例隔离候选，不将其直接标为患者求解输入。旧鼻腔域保留为分段对照；扩展域若继续在原鼻咽出口截断，将无法观察新纳入的下游区域，因此必须重新确认出口。

## 当前可定位事实与未知

- 既有`nasal_pipeline.py:34`及`ts_quality_gate.py:25`仅将左右鼻腔与鼻咽列为气流域。
- 本机模型标签定义还含口咽、下咽；喉腔标签属于另一模型任务。标签语义、非空、真实图像覆盖和专业正确性是分别需要验证的事项。
- 五例已生成CT与语义标签，可先复用已有输入查证，避免启动新一轮推理；输入哈希在T-026落盘。
- p编号与患者A/B的对应、症状准确部位、所需下界未取得可核验证据；工程单例不可命名为患者B。
- 全域无扫描边缘接触、STL闭合、可生成网格，各自均不能证明目标咽喉完整或临床解释成立。

## 后续依赖与停止条件

1. 王湧瑞复核：病例对应、症状位置、影像是否覆盖目标区域、各段边界、目标下方出口及口腔处理方式；需要与具体CT/候选哈希绑定。
2. 下界不在现有扫描覆盖内，不能用模板或插值补齐。记录所需覆盖区域供临床团队评估现有可用检查，不自行要求患者重复CT。
3. 专业边界确认后，才冻结扩展几何、出口及分段测量面，并验证新网格/边界条件。未经确认的下界保持待外部输入，不自动在CT边缘设出口。
4. 报告分别呈现鼻腔、咽部与全域的同工况指标。旧域压降不能直接替换为扩展全域压降；静态流场本身不作为不适因果、动态塌陷或治疗效果的结论。
5. 网格与求解沿既有单CPU车道；输入变化重新校验哈希及依赖证据，T-011的旧入口失败不因本扩展自动放行。
