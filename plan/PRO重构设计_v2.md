> 缘起：用户批评「你完全不要管我们目前的网页内容，先理解这种工具类的全链路再继续」。
> 本文只谈架构理解与设计，不是代码。证据：SolidWorks 官方 UI 文档（help.solidworks.com 2014–2024）、
> SimScale Workbench 2.0 文档、ANSYS Workbench 状态语义、COMSOL/OpenFOAM 建模对象分析（2026 检索）。

## 一、工具类软件的五条第一性原理（每条有证据锚点）

### P1 · 建模对象（modeling object）唯一且明确
每个工具都有且只有一个「用户每天在编辑的对象」：
- SolidWorks = **特征历史树**（FeatureManager design tree，chronological backbone）；
- Fusion 360 = **时间线**（同款概念的横向变体）；
- COMSOL = **单棵参数化模型树**（几何→物理→网格→研究→结果全在树里）；
- STAR-CCM+ = **Simulation 树**（每个边界/物理模型/报告都是树节点）；
- OpenFOAM = **case 目录**（文本字典可审计）。

**我们的建模对象 = 患者项目，其内部应是一棵「参数化处理树」**，不是一堆松散页面。

### P2 · 依赖链是中枢神经（dependency chain）
树的每个节点记录三样：输入（对前序产物的引用）、参数（可编辑）、产物。
改前序节点 → 后序自动受影响。SolidWorks 官方：特征按创建顺序自上而下，
父子关系使「改动早期特征，全部后续特征自动重算」。
**对应我们：分割参数改了 → 几何/网格/求解/报告全部应标「过期」——这就是 stale 传播。**

### P3 · 属性管理器与图形区共生（PropertyManager 哲学）
SolidWorks 官方设计理由原文：PropertyManager「显示实体或特征的属性，
这样您可指定属性而**没有对话框盖住图形区域**」。
**图形区（三维）是永久主角；编辑参数不模态、不遮挡、不跳页。**
选中树节点 → 属性面板就地编辑 → ✓存/✕弃（SimScale 同构）。

### P4 · 状态语义驱动全部视觉（state semantics）
ANSYS Workbench：每个 cell 有 update-states（green check = complete & **up-to-date**，
refresh/stale/pending 等）。状态不是装饰，是**依赖链求值的结果**：
一个节点的状态由「自身产物是否存在」+「所有上游是否都是 fresh」共同决定。
**我们的节点状态必须这样算，不能是「有没有跑过」的静态记录。**

### P5 · 配置是变体，不是复制（Configuration）
SolidWorks ConfigurationManager：同一模型多组态，不复制文件。
**对应我们：同一患者的多个求解配置（层流/k-ω、maxh1/maxh04）= 配置维，
应该是项目树下的并列分支，共享上游，各自有独立求解与产物。**

## 二、我们的全链路（患者项目处理树）

```
患者项目（Project）
├─ 01 数据源（CT 序列）          [参数：序列选择/阈值]      [产物：series_manifest]
├─ 02 分割（气道掩膜）            [参数：模型/阈值]          [产物：mask]
├─ 03 定位（开口/标志点）         [参数：候选点集]           [产物：landmarks]
├─ 04 几何（STL 表面）            [参数：平滑/修复]          [产物：surface.stl + 门禁报告]
├─ 05 网格（体网格）              [参数：maxh/边界层]        [产物：mesh.msh + checkMesh]
├─ 06 求解配置（Configuration 维） ┆ 每配置一分支：
│   ├─ 配置 A：层流 · maxh1.0     [参数：求解器/BC/预设]     [产物：case + field]
│   ├─ 配置 B：k-ω SST · maxh1.0  [参数：湍流模型/壁面处理]   [产物：case + field]
│   └─ 配置 C：层流 · maxh0.4     [参数：网格档位]           [产物：case + field]
├─ 07 后处理（按配置归属）         [产物：Δp/R/WSS/流线/VTK]
└─ 08 报告（按配置归属）           [产物：对照表/结论]
```

每个节点：{inputs: [前序产物引用], params: {...}, state: fresh|stale|missing|running|failed, artifacts: [...]}。
**状态推导**：state = f(自身产物存在性, 全部上游 state)。上游 stale → 本节点 stale（级联）。
这直接复用我们已有的工程纪律（T-046 的 asset 机制、输入指纹 sha256、准入绑定快照）——
**后端早已按依赖链设计，缺的是前端把这棵树如实画出来。**

## 三、PRO v2 界面（原理 → 布局）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：项目切换 · 全局状态 chips · 操作（运行/刷新）              │
├────────────┬──────────────────────────────────┬──────────────┤
│ 处理树      │ 图形区（永久主角）                  │ 属性管理器      │
│ 患者项目     │ 三维表面/切片/流场                  │ 选中节点的：     │
│ ├01 数据源 ✓│ （三维常驻；属性编辑不遮挡不跳页）     │ · 参数（可编辑） │
│ ├02 分割  ✓│                                  │ · 输入引用      │
│ ├03 定位  ✓│                                  │ · 产物        │
│ ├04 几何  ✓│                                  │ · 状态+原因    │
│ ├05 网格  ◌│                                  │ · [运行/重算]   │
│ ├06 配置    │                                  │              │
│ │ ├A 层流 ✓│                                  │              │
│ │ ├B k-ω ▷│                                  │              │
│ │ └C maxh04◌│                                 │              │
│ ├07 后处理 ◌│                                 │              │
│ └08 报告  ◌│                                  │              │
├────────────┴──────────────────────────────────┴──────────────┤
│ 状态栏：当前动作 · 依赖求值结果（如「04 几何因 02 参数变更而过期」） │
└──────────────────────────────────────────────────────────────┘
```

与 SolidWorks 的对应：处理树=FeatureManager｜属性管理器=PropertyManager（不遮挡图形区）｜
配置=ConfigurationManager｜状态栏=status bar｜stale 传播=特征重算语义。
