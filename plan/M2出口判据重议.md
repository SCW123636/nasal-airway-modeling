## 2. 「收敛」有三层含义——先分清，再选判据

| 层 | 含义 | 判据来源 | Run 1 实测 | 契约屏（`cfd_contract.py:389-396`） |
|---|---|---|---|---|
| **L1 残差收敛** | 初始残差降到 `residualControl` 阈值，打印 `SIMPLE solution converged in N iterations` | `residualControl {p 1e-6; U 1e-6}` | **未达**：终局 Ux **9.80e-05** / p **2.60e-04**（阈值上方 10–260×）；残差 T≈460 触底 7.71e-5 后**缓升 +27%**，非单调 | `target_residual_max` 默认 **1e-5** → **不通过** |
| **L2 工程稳态** | 监测量（Δp / 分流 / 不平衡）在窗口间相对变化 ≤ 屏值 | controlDict functions 逐 iteration 记录 | **已达**：Δp 窗间最大相对变化 **0.0079%**（t≥101 起 430 步稳定在 10.29–10.31 Pa）；分流恒 0.500000（等分 BC 保持）；不平衡 t≥100 后 ≤6.8e-6、终值 **7.2e-7** | `maximum_monitor_relative_change` 0.5% → **通过（约 63× 裕量）**；`maximum_mass_imbalance_fraction` 0.5% → **通过（约 7000× 裕量）** |
| **L3 不崩** | 无 FOAM FATAL / sigFPE，越过 T-004 崩溃点并持续 | — | **已达**：533 步；越过 T=260 崩溃点 273 步 | — |

**契约本身已内置分层声明机制**（`cfd_contract.py:385`）：
`numerical_validation ∈ {unchecked, failed, passed_engineering_screen}`。
Run 1 的诚实声明是 **`unchecked`**——**不是** `passed_engineering_screen`（residual_max 超目标）。
即：不造假也有合法的路可走，问题只在 M2 的出口词写的是哪一层。

## 5. 重议中发现的两个契约侧缺口（建议一并处置，但不改判据迁就结果）

1. **`mass_imbalance_fraction` 取值口径未定义**：全程 max **6.33e-3 发生在 t=2**（启动瞬态，初始场不无散）；
   t≥100 已 ≤6.78e-6、稳态段 ≤1.74e-6。若契约取「全程 max」则 Run 1 **不通过** 0.5% 屏——
   而这是个初始场假象，不是求解缺陷。建议明确「取稳态段（末 N 步）值，瞬态另列」。
2. **`monitor_relative_change` 未定义监控量与窗口**：本文件用「Δp 窗间相对变化（末 40% 样本、窗长 20、
   窗口均值逐窗比）」作操作定义（实测 0.0079%），需写进契约或工程屏文档。
3. ⚠️ `target_residual_max 1e-5` 对本网格是否可达**未知**（H1–H3 判别后再谈是否修目标值）。
   **现在不修**——避免「为迁就结果改判据」的新一类事故；若用户选 B/C 拿到更低残差底，再议。
