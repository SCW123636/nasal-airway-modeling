## 二、逐块说明：是什么 + 可用于什么

### 【0】0.35 mm 各向同性（浙一 · Philips Incisive CT）—— 项目主力用例

**是什么**（实测）

| 项 | 值 |
|---|---|
| 序列 | `Bone 0.35mm ISO`（kernel YB）+ `Soft 0.35mm ISO`（kernel UC） |
| 体素间距 | **0.349609 × 0.349609 × 0.35 mm**，512×512 |
| 层数 | 各 394 帧（被拆成 3 个 zip：part1=1–132 / part2=133–264 / part3=265–394） |
| z 覆盖 | −703.79 → −566.24 mm，跨度 **137.55 mm**，393 个间隔全 = 0.35，**无跳层** |
| HU | Bone −1024…3716 / Soft −1024…3307，`RescaleIntercept = −1024` |
| 传输语法 | 未压缩 Explicit LE（1.2.840.10008.1.2.1），16 bit |
| 协议 | `StudyID = sinus`，`ProtocolName = sinus orbit`，`BodyPartExamined = FACE`，HFS |
| PHI | **头部已无 PHI**（PatientName / PatientID / InstitutionName 等字段整体不存在） |
| 拼接验证 | 三个 part 可拼成**单一连续体数据**：dz 唯一值 {0.35}，最大跳变 0.35 mm，单调递减 ✅ |

**可用于什么**

- **唯一能直接做 CFD 网格的数据**：0.35 mm 真各向同性，优于 SOP 要求的 ≤1 mm。
- **S2 鼻腔分割算法的主开发用例**：全链路（DICOM→STL→Blender→后处理）只在这一例上跑通过。
  分割的金标准标注、算法迭代、参数扫描都应该放这里。
- **S3 几何修复与开口处理的试验台**：当前「STL 是封闭壳体、没有鼻孔/鼻咽开口」这个硬阻塞，
  只能拿它调。
- **两套（bone/soft）共享同一体素网格**（IPP/IOP/尺寸差值全 0）→ 可叠着用，无需配准。
- **边界**：单例。**它回答不了"方法是否通用"**——而这正是三患者批次的价值所在。
  另外，"纯自动分割无可靠解"这个结论本身就是在它身上、且在 0.35 mm 这个最有利条件下得出的。

### 【1】患者1 · 深圳二院 · 联影 uCT 760

**是什么**：2026-01-27 单次检查，514 帧，9 个序列。
最佳骨窗 `1.0 x 0.8 Bone`（H_SHARP_C）：136 层，**实算 dz = 0.8 mm**，面内 0.3477 mm（三例里最细）。

**可用于什么**
- **层厚鲁棒性下限测试**：0.8 mm 是四例里最厚的体数据骨窗，用来看方法在真实常规档位下还成不成立。
- 同患者还带 `1.0 x 0.8 Soft-3D`（与骨窗同网格）+ `3.0 x 3.0` 厚层 + 4 个 `3D_Sinus^` 冠状重建
  → 可做**软组织与骨窗配准一致性**的对照。
- **不可用**：`3D_Sinus^_1~4`（3.0 mm 厚层 + `intercept = 0`）、`3.0 x 3.0` 系列。

### 【2】患者2 · 复旦眼耳鼻喉 · 西门子 SOMATOM Definition Flash

**是什么**：2025-09-02 单次检查，380 帧，7 个序列。
最佳骨窗 `Sinus 0.75 H40s`：286 层，**标称 0.75 实测 dz = 0.5 mm**，面内 0.459 mm（四例里最粗）。

**可用于什么**
- **跨厂商泛化测试**：唯一的西门子序列。核（H40s 平滑核）与联影 H_SHARP_C / H_VSHARP_C 差异明显，
  是检验"H 阈值判据是否依赖厂商核"的唯一样本。
- **层厚最好但面内最粗**的互补样本：dz 0.5 优于患者1，面内 0.459 差于患者1
  → 可用于分离"轴向分辨率"与"面内分辨率"各自对分割的影响。
- 同患者带 `Sinus 5.0 H41s` / `H70h`（5 mm 厚层），只能做定位参考。

### 【3】患者3 · 湘雅三院 · 联影 uCT 710 / uCT 968 —— 唯一双时点

**是什么**：**两次检查**。
- 2025-07-09：`1.0 x 0.5_bone`（H_VSHARP_C），232 层，dz = 0.5 mm，面内 0.4668 mm
- 2026-02-17：`0.6 x 0.6_BONE`（H_VSHARP_C），186 层，dz = 0.6 mm，面内 0.3672 mm
（2026-02 那次 `202` 与 `203` 两个目录都是 `0.6 x 0.6_BONE`，内容同规格，需注意别当两套用。）

**可用于什么**
- **唯一同患者纵向配对资源**：可直接对比两次检查的鼻腔几何变化，
  对上需求方要的"**左右侧通气分配**"这个指标——四例里只有它能做纵向一致性。
- **同患者不同层厚（0.5 vs 0.6）+ 不同设备（uCT 710 vs 968）** → 天然的分割稳定性测试。
- 帧数最多（1555），是序列最全的一例，适合做采集规格筛选规则的回归测试。
- **不可用**：`3D_AB_1/2/5`（2.0 mm + `intercept = 0`）、`CH` / `CH_4`（2.0 mm + `intercept = 0`，
  且 `3D_AB_1` 里混进了一张 Secondary Capture 截图，排序后造成 106 mm 假跳变）。

### 【附】三个 `nose.stl`（各患者目录下）

**是什么**（二进制 STL 头实测）：患者1 = **631,868** 面；患者2 = **650,396** 面；患者3 = **772,228** 面。
文件大小与 `84 + 50×面数` 完全自洽，是合法二进制 STL。**80 字节头全为 0x00**，没有任何生成工具/参数记录。

**可用于什么**：**只能当"别人做过一版"的形态参考。**
- **不能当金标准**：生成方法、分割参数、阈值口径全部未知，也无从复现。
- 可用作**形态交叉核对**：比如把我们的鼻腔跨度/体积和它对一下量级，看差多少倍。
- ⚠️ **一处待澄清（不是矛盾，是口径不明）**：`全自动链路进展报告（第二份）.md` 记的是
  「30.3 万面 → 9.0 万面」，那说的是 **0.35 mm 那一例**的产物；而这三个 STL 是 **63–77 万面**。
  数据更差的病例反而面数更多，这一点需要问清（是不同分割参数？不同简化容差？还是根本来自另一版分割）。
  **问清之前不要引用任何一方的面数当基线。**

## 四、这份清单暴露的三处口径冲突（未裁定，落地前必须先定）

1. **阈值**：我方 SOP −300 vs 外部需求方 −400（差 100 HU 会改变鼻腔-鼻窦边界）
2. **出口边界**：SOP「出口 0 Pa」vs 录屏「18 Pa」vs 方法记录「咽喉处为正常出气口」
3. **输入格式**：录屏走 STL vs 方法记录提示 MITK（MITK 强项正是直吃 DICOM，不必转 STL；
   而转 STL 恰是当前「开口丢失 + 无单位」两个硬阻塞的来源）

## 五、一句话总结

**0.35 mm 那 788 帧是所有事的底座**（唯一真各向同性、唯一跑通全链路），
**三患者那 2449 帧是用来证伪"方法通用"的**（4 家医院 4 个厂商，含唯一双时点），
**三个 `nose.stl` 只能当参考、不能当标准**，
**两份新文档是外部口径的来源，也带来了必须裁定的第三处冲突。**
