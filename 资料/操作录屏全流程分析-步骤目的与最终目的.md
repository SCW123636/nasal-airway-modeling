## 零、先说最终目的

**不是"做个好看的流线图"，是给鼻腔填充/结构重建手术提供客观量化依据。**

这条链路全部动作，最终服务于三件事：

1. **把主观主诉变成可比数字** —— 患者说"吸不到气、过度空旷"，这是主观的；速度场、压力降、壁面剪切应力是客观的，能左右对比、能前后对比、能拿到医生面前谈。
2. **改变"凭经验盲做"** —— 填充位置、角度、剂量现在靠医生个人手感，术前无法预判；有了数字化的鼻腔模型和流场，才能先试算再下刀。
3. **闭环到个性化鼻腔衬片（鼻塞）** —— 流场数据反过来指导衬片形状设计，实现 CT → 气流建模 → 衬片设计的完整闭环。

用患者方的原话说：**"把患者主观的通气不适转化为可以看见和比较的气流数据。"**

而**在自动化项目语境下**，这条录屏还有第二重身份：它是**人工基准流程（金标准）的操作留档**，用来给后续"输入 DCM → 输出 STL → 输出 CFD"的全自动系统做对照。换句话说，它记录的不只是"怎么做"，更是"每个决策点人工是怎么判断的"——这些判断点正是自动化的靶子。

## 一、全局：五步与一条主线

```
CT 原始数据 ──► 分割 ──► 修复 ──► 加空气域 ──► 求解 ──► 后处理
  DICOM        Slicer   Blender    SimScale    SimScale   SimScale
   ①            ②         ③          ④           ⑤          ⑥
```

**现场纠正一处**：项目文档（需求文档 3.1 节、SOP v2.0）把流程写成"五步"，其中空气域构建被并入"SimScale 求解"。但从录屏实际动作看，**在 SimScale 里加两个圆柱并把它们与气道 Union 成一个体，是独立的一个几何步骤**，而且它是整条链路里最容易出错、后果最严重的一步（后面详述）。我按六步拆解。

**贯穿全程的一条主线：保拓扑、保朝向、保开口。**

- **保拓扑**：气道必须是一个封闭、连通、无自交的实体，否则 CFD 网格划分失败 → 求解失败。
- **保朝向**：法向必须朝外一致，否则求解器分不清哪边是流体、哪边是固体。
- **保开口**：鼻孔和鼻咽两端必须保持贯通且被明确标记为边界，否则无法定义进气/出气条件。

这三条在每一步都出现一次，是理解所有操作目的的钥匙。

## 二、逐步拆解：每个动作在解决什么问题

### 步骤一：3D Slicer 分割 —— 把 CT 灰度变成"空气所在的空间"

| 动作 | 目的（解决什么问题） |
|---|---|
| 载入 DICOM 序列（源体 `3: 1.25SH_6`，层厚 1.25 mm） | 拿到带 HU 值的体素数据。**1.25 mm 这个层厚决定了精度上限**——后续所有几何细节都不可能比这更细 |
| 设置阈值 `−3024 ~ −400 HU` 并 Apply | 空气的 CT 值约 −1000 HU；低于 −400 的体素基本是空气。**这一步的产物不是"气道"，而是"所有空气的候选集合"**——包括体外空气、鼻窦、咽鼓管、含气肠管等一大片无关区域 |
| 放大到鼻孔附近 | 建立解剖坐标系，找到后面要下刀的位置 |
| Scissors（Erase inside + Free-form 自由绘制）在鼻孔平面下刀 | **切断鼻腔内空气与外部空气的连续性**。这是整步最关键的一刀：如果不切，3D 视图里鼻腔和体外空间是同一块连通区域，任何"只保留鼻腔"的后续操作都无从下手 |
| （文档/需求对应）Islands → Keep selected island | 保留与点击点连通的唯一一块，其余全部丢弃。**把"空气候选集合"收敛成"鼻腔主气道"** |
| Show 3D 预览旋转检查 | 目视确认：有没有破洞、毛刺、断裂；鼻孔和鼻咽两端是否都还开口 |
| Export to files → STL | 交付一个纯几何文件。**STL 不带患者隐私**，这是文件格式选择上的隐私收益 |

> **这一步的本质**：一个连通性判断问题。医学解剖知识在这里起唯一作用——"哪块空气算鼻腔、哪块不算"。而"是不是连通"是纯几何问题。两者的边界就是人工介入的位置。

**ENS 患者的特殊难点**（来自需求文档 3.2）：下鼻甲切除后鼻腔异常宽大，阈值分割的边界极易出错，必须逐层手动修正。残留的凹陷、瘢痕腔隙——**与主气道连通且实际有气流通过的计入气道，盲端腔隙排除**。这是个硬判断，没有算法能替人做。

### 步骤二：Blender 修复 —— 让网格"经得起 CFD 的考验"

分割出来的 STL 是**表面网格**（三角片），不是请实体。CFD 求解器要的是封闭实体，所以必须修。

| 动作 | 目的 |
|---|---|
| 拖入 `Segmentaion_5.stl`（面数 **236491**，尺寸 **98.7 × 115.859 × 106.021 mm**） | 检视原始网格规模与真实尺寸 |
| 修正单位（默认按"米"读，显示成 98674 mm 级错乱） | **尺寸必须正确**——CFD 里所有物理量（速度、压力降）都依赖真实尺度，单位错 1000 倍，结果全废 |
| 启用 **3D Print Toolbox** 插件做检查 | 查非流形边、翻面、自相交、退化面 |
| `精简`（Decimate）减面 | 原始 23.6 万面太大，**目标压到 3–10 万面**（SOP 规定）。面数直接决定网格划分时间和求解算力；而 SimScale 免费版只有 10 个项目配额，省算力就是省配额 |
| 检查非流形（3D Print Toolbox 报告的 `非流形 9`、`锐边 5`、`悬空面 29010`） | 量化修复对象：**哪里破、哪里翻、哪里退化** |
| 导出 STL | 交付 `airway_clean.stl` |

> **这一步的本质**：几何质量工程。项目文档明确写"**几何修复（阶段三）是耗时最长且技术难度最高的环节**"，SOP 给出的人工耗时是 **2–4 小时**（熟练后 30–60 分钟）。这是整条链路最大的时间陷阱，也是自动化最该攻的地方。

**⚠️ 这里有个重要的判断分歧，必须单独说**：会议记录里有一句"网格模型不精准对最终气流模拟影响不大，因为仿真软件会体素化处理并填充内部通道"。**这句话只在"气道内部是大片空腔"的假设下成立**。鼻腔恰恰不是大片空腔，它是**狭窄、复杂、多褶皱、宽度常与 CT 层厚同量级**的通道。在 1.25 mm 层厚下，体素化会把最窄处（鼻阀区）直接抹掉或封死。**所以"修复不精准没关系"这个结论不能直接套用到鼻腔气道模型上**——这是我基于几何尺度给出的判断，建议在联调时用同一份 STL 做低精度/高精度两次划分来验证。

### 步骤三：SimScale 加空气域 —— 把"气道壁"变成"流体域"

**这一步最反直觉，也最关键。** 从 Slicer 导出的是**气道内空气的表面**（也就是鼻腔壁上那一层空气的边界），它内部是空的、外面也是空的——本质是一张"皮"。要算流体，必须把这张皮**变成一个封闭的体积**，里面装着空气。

| 动作 | 目的 |
|---|---|
| Import `test111.stl` 进入项目 `nöse3` | 载入气道几何 |
| 加第一个 `Cylinder`：**Height 80 mm / Radius 25 mm**，Center `(0, −40, −73)` | **做鼻咽侧的出口延长段**。真实鼻腔末端是开放的，直接截断会在截面上产生不真实的边界效应；加一段直管把边界推远，让出口处的流场充分发展 |
| 加第二个 `Cylinder`：Center `(5, 45, −80)`，轴向分量绕 Y `0.17`（约 9.7°） | **做鼻孔侧的入口延长段**。会议记录明确要求"进气口与鼻孔相交的截面，**方向斜向上**"——`0.17 rad` 这个倾斜就是模拟自然吸气方向 |
| 把气道 + 两个圆柱 → `Union` 合并 | **得到单一封闭实体**，这就是 CFD 的**计算域（流体域）**。三个部件必须成为一体，否则求解器会认为是三个独立区域 |

> **这一步的本质**：把解剖几何转成工程几何。两个圆柱不只是"延长管"，它们是**入口/出口边界条件的物理载体**——后面设的 0 Pa 和 18 Pa 就加在圆柱的端面上。

**这是整条链路最脆弱的一环，三个风险点：**

1. **接口是硬接的**。圆柱直接 Union 到鼻腔几何上，接口处没有倒角、没有过渡、没有平滑。圆柱半径 25 mm 相对鼻腔内部尺度偏大，接口处会形成一个**突缩/突扩**。当进出口压差只有 18 Pa 这种小量级时，**接口处的局部损失会显著污染总压降结果**——而鼻阻力恰恰就是总压降算出来的。这是本录屏最实质的技术缺陷。
2. **Union 失败风险**。如果 STL 有自交或破洞，布尔运算会失败或产生畸形体。录屏里 Union 显示 `Checking Faults 1 of 1 bodies`，说明确实做过容错检查。
3. **单位一致性**。SimScale 里的 mm 与 Blender 里的 mm 必须对齐，否则圆柱会跑到模型外面去——录屏中作者反复调 Center 坐标，本质上就是在手动对准这个位置。

### 步骤四：建仿真 —— 选定物理模型

`Create Simulation → FLOW → **Incompressible**`（Community 计划）

| 设置项 | 值 | 为什么这么选 |
|---|---|---|
| 分析类型 | Incompressible | 鼻腔气流远低于 Mach 0.3，空气不可压假设完全成立 |
| 材料 | **Air**：ν = `1.529e-5 m²/s`，ρ = `1.196 kg/m³`，Newtonian | 直接取内置空气材料。注意 ρ=1.196 对应常温常压，**没有考虑鼻腔内 34–37 ℃ 的加温效应** |
| 湍流模型 | **k-omega SST** | 医学上鼻腔气流由层流转湍流。SOP 规定"入门用 Laminar，**科研用 k-ω SST**"——选 SST 是把它当正经研究做，不是跑通就算 |
| 时间 | **Steady-state** | 稳态。**这是本录屏最大的科学性妥协**，下面单独说 |
| 算法 | **SIMPLE** | 压力-速度耦合的标准定常算法，与 Steady-state 配套 |

> **关于 Steady-state 的诚实评价**：真实呼吸是**周期性的**——吸气、停顿、呼气，流速随时间变化，鼻腔内还存在明显的涡旋脱落。稳态求解把整个呼吸周期抹成一个恒定流场。**做形态示意（气流走哪条道、哪里是高速区）可以；做阻力、压降的定量结论，严格说站不住**。SOP 里没提瞬态，说明这套基准流程本身就没打算做到那一步。**如果最终交付要给医生看鼻阻力数字，这里必须升级为瞬态（Transient）并用呼吸波形驱动入口流速。**

### 步骤五：边界条件 + 网格 + 求解

| 动作 | 目的 |
|---|---|
| `Pressure inlet 1` = **0 Pa（total pressure）**，Turbulence Automatic | 入口定总压为参考零点 |
| `Pressure outlet 2` = **18 Pa（gauge, fixed value）**，面 = `Bottom@test111` | 出口定 **18 Pa 表压**（约 1.8 cmH₂O）。**这个压差就是"驱动力"**——两侧压差驱动气流从入口流向出口，模拟一次吸气的驱动条件。18 Pa 是平静呼吸的合理量级 |
| 材料指派 | `Air` 指派给体积 `test111`，确认计算域内只有空气 |
| `Mesh 13`：Fineness 5，预估 **215.6k–323.4k cells / 63.2k–94.9k nodes** | 生成体网格。30 万级网格是 SOP 给的"入门～中等"区间（SOP 说科研用 30 万–200 万） |
| `Run 1` 提交 | 云端求解。实际 **74 min，9.90 core-hours**，`Finished` |

> **关于边界条件方向性的一个关键点**：SOP 写"入口静息呼吸双侧约 15 L/min，出口 0 Pa"——**这是速度入口/压力出口的写法**。而录屏用的是**压力入口/压力出口**（0 Pa → 18 Pa），**根本不给流量值**。这两者语义完全不同：前者你指定流量、算压降；后者你指定压降、算流量。录屏的做法省掉了流量标定，但代价是**算出来的流量是多少你得自己去后处理里读**，且不一定等于 15 L/min。**汇报时不能把这两个口径混用。**
>
> **另一处**：录屏只有一个入口、一个出口。而真实鼻腔是**双侧**的，左右鼻孔都可能参与呼吸。单入口意味着要么这例患者单侧不通，要么作者把两侧简化成一个。**这在鼻中隔偏曲、左右通气不对称的病例上会直接丢失关键信息**——而左右通气失衡恰恰是鼻腔手术最关注的指标之一。

### 步骤六：后处理 —— 把数字变成能看的东西

| 动作 | 目的 |
|---|---|
| `Solution Fields` → `Cutting Plane 1`，Opacity 0.9 | 切面速度云图。**看"哪个截面速度高、哪个区域是低速死区"** |
| `Particle Trace 1`：seeds 19×19，Spacing 1.2e-3，Size 1.7e-4，Cylinders，Trace both directions | 三维流线。**看"气流走哪条道、是否直冲、有没有涡旋"**——这是最直观、最适合给患者看的图 |
| `Parts Color` / 色标 `Velocity Magnitude`，范围 **0 ~ 3.552 m/s** | 统一色标量纲。3.55 m/s 峰值对平静呼吸偏高，但对窄通道或高压差情形属合理量级 |
| `ITERATIONS 1000` | 确认迭代收敛（残差达标） |

> **后处理真正该产出但录屏没做的**：鼻阻力（总压降 ÷ 流量）、壁面剪切应力（WSS）、左右侧流量分配、总鼻道/嗅区通气比例。这些才是能让医生拿去谈手术的**量化指标**。录屏只做到了"看图"，没做到"出数"。

## 三、目的分层：每一步服务于哪一层目标

| 层次 | 目标 | 由哪些步骤支撑 |
|---|---|---|
| **L1 可见** | 让气流"看得见" | 步骤六（流线、云图）——最表层，也是给患者看的那层 |
| **L2 可比** | 让不同方案、术前术后能对比 | 步骤一（统一分割标准）+ 步骤四（统一物理模型）+ 步骤六（统一色标）。**必须是同一套标准，否则不可比** |
| **L3 可量** | 输出鼻阻力、WSS 等客观数字 | 步骤三（几何质量）+ 步骤五（边界条件口径）。**这两个环节的误差会直接进入最终数字** |
| **L4 可判** | 支撑手术决策、推导衬片形状 | 全链路。**这一层才是项目的最终目的** |

**关键判断**：录屏作为"人工基准流程"是**合格的**（流程完整、参数明确、可复现）；但作为"能支撑临床决策的数据源"是**不足的**——它停在 L1–L2，缺 L3 的定量，也就到不了 L4。

## 四、对自动化项目的直接映射

录屏里每一个"人工判断"点，就是自动化的一个待攻克靶点：

| 人工动作 | 自动化难点 | 当前状态 |
|---|---|---|
| 阈值分割 `−3024 ~ −400 HU` | 阈值需按病例微调，固定值必然失效 | 已有 v2–v9 多版分割脚本 |
| **鼻孔平面下刀切断内外部空气** | **最难**——位置依赖解剖标志，没有固定坐标 | 人工 |
| Islands 保留主气道 | 纯连通性算法，可自动 | 可自动 |
| 逐层手动修正（ENS 患者） | 需要解剖知识，最耗人工 | 人工 |
| Blender 修复（填洞/去重/法向） | 算法明确，可自动 | 已验证可自动 |
| **判断"哪个腔隙算气道"** | 盲端 vs 通气腔隙的语义判断 | 人工，需标注协议 |
| **加圆柱延长段** | 位置、角度、半径需按解剖自适应 | 人工 |
| 判断进出口位置正确 | 需解剖标志 | 人工 |
| 求解设置 | 参数固定，可模板化 | 可自动 |

**一句话**：录屏里 "可自动" 的已有算法路径，"需解剖判断" 的才是真正的技术壁垒。项目文档把这层叫"AI 输出几何是否经得起流场考验"——**验证的靶点就是这张表里后四项。**

## 五、必须记住的五条

1. **最终目的是给手术提供量化依据**，不是做演示动画。所以"流线好不好看"不是验收标准，"鼻阻力算得对不对"才是。
2. **步骤三（加空气域）是最脆弱的一环**。接口硬接造成的局部损失会污染鼻阻力——而鼻阻力是核心指标。这个缺陷在录屏里真实存在。
3. **稳态求解不支持定量结论**。要做鼻阻力数字，必须上瞬态。
4. **边界条件口径不能混用**。SOP 写"流量入口 0 Pa 出口"，录屏用"0 Pa 入口 18 Pa 出口"，两者算出的东西不一样。
5. **单入口丢失左右通气信息**。鼻腔手术最关注的左右不对称，在单入口模型里看不见。
