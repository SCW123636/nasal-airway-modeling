## 一、鼻腔分割：为什么纯自动无解（本轮核心结论）

### 1.1 四类方法，四类失败

| # | 方法 | 结果 | 决定性数据 |
|---|---|---|---|
| 1 | 自研形态学判据 v1–v9（上轮） | ❌ | 最佳 v9 左右对称比 **0.175**；z≥190 分割崩溃 |
| 2 | Slicer 阈值 + 连通域 | ❌ | 空气 **38,607,700** 体素；**66,036** 个连通分量；最大分量 **38,239,181（99%）**，且 **bbox 六个面全部接触图像边界** |
| 3 | 内部空洞法（fill_holes） | ❌ | 空洞仅 **327,354** 体素（占全体积 **0.32%**），比真空气少 **两个数量级**；最大空洞是乳突气房（8,483 体素）而非鼻腔 |
| 4 | 区域增长 + 解剖护栏 | ❌ | 无护栏生长 38,239,181；加护栏压缩到 **781,177**（护栏本身有效，压缩 98%），但结果形状是**护栏矩形硬边界切出的方块**，且越过骨壁长入上颌窦 |

### 1.2 根因（确定性，非推测）

**鼻腔与上颌窦、筛窦在 CT 的 HU 值上同为"空气"（< −300 HU），且通过解剖学上的自然开口互相连通。**

- 通过 **鼻孔** 与外部大气连通 → 方法 2、4 无法把鼻腔与外界分开
- 通过 **上颌窦自然开口 / 筛窦开口** 与鼻窦连通 → 方法 1、4 无法把鼻腔与鼻窦分开
- 鼻腔 **不是封闭空腔** → 方法 3（fill_holes）根本抓不到它

**这三条连通性都是真实解剖结构，不是影像质量问题。**

### 1.3 这意味着什么

SOP 第七节写的解法是准确的：

> "分割时鼻腔与外部空气连在一起：在鼻孔平面用 Scissors 或 Erase 切断连接处，再用 Islands 工具保留鼻腔主体。"

**关键在 "Scissors" 这个词 —— 它是手工操作。** 录屏里的专家也是手工画的。
要自动化，就必须把"鼻孔在哪、鼻腔边界在哪"这个**解剖判断**编码成规则；
而鼻腔在冠状面上逐层剧烈变化（前部窄、中部宽、后部收窄成鼻咽），固定形状判据必然失效。

### 1.4 三条可选出路（供决策）

| 方案 | 说明 | 代价 |
|---|---|---|
| **A. 半自动**（推荐） | 脚本自动定位鼻中隔、鼻腔中心线，只把「鼻腔↔鼻窦接口」标出来给人工确认一两笔，其余全自动 | 每例需 1–3 分钟人工确认 |
| **B. 换专业工具** | 用 TotalSegmentator（有 head/airway 预训练模型）或 Slicer 的 AirwaySegmentation 扩展 | 需联网下载模型权重；结果需验收 |
| **C. 骨架/管状性判据** | 计算空气域三维骨架，找从鼻孔出发、管径受限、不进入上颌窦的路径 | 需多轮迭代，不保证成功 |

| pq | `pqComponents` / `pqPython` / `pqApplicationComponents` | ❌ 级联失败 |

同时用 PE 导入表**递归解析**（`pe_imports_tree.py`）确认：
**`pq*` 系列的静态依赖链完整，零缺失** → 故障在**运行期 DllMain 初始化**，不在"缺文件"。

### 3.2 根因

**本机 Windows 的 UCRT API Set 存根残缺：**

- `C:\Windows\System32` 下 `api-ms-win-*.dll` 数量 = **0**（正常 Windows 11 应有上千个）
- `System32\downlevel` 下仅 **111** 个，且**缺** `api-ms-win-shcore-scaling-*`、
  `api-ms-win-core-winrt-l1-1-0`、`api-ms-win-core-winrt-string-l1-1-0`
- VC++ 2015-2022 Redistributable (x64) **已正确安装**（14.44.35211）→ **不是它的问题**

### 3.3 已排除的方案

- ❌ 把 6 个 `api-ms-win-crt-*.dll` 从 `downlevel` 复制到 ParaView `bin/` → **无效**（实测）
- ❌ 在 ParaView 目录内以任何方式补 DLL → 无效，缺的接口在系统层面就不存在

### 3.4 修复路径（需人工决策）

1. **重装/修复官方 VC++ 2015-2022 Redistributable (x64)** —— 它会修复 UCRT 注册（推荐先试）
2. **系统还原 / DISM 修复**：`DISM /Online /Cleanup-Image /RestoreHealth` + `sfc /scannow`
3. **改用替代方案**（已实测可行，见下节）

## 六、下游链路两个硬阻塞（下一步必修）

### 6.1 STL 无开口 —— **最关键的阻塞**

实测：`boundary_edges = 0`，`islands = 1` → **这是一个完全封闭的壳体，没有任何开口**。

而 CFD 边界条件需要至少两个开口面：
- **鼻孔侧入口**（对应 SOP 的"入口静息呼吸双侧约 15 L/min"或录屏的"0 Pa total"）
- **鼻咽侧出口**（对应"出口 0 Pa"或录屏的"18 Pa gauge"）

SOP 红线明确：

> "Blender 修复时只补内部破洞，鼻孔与鼻咽开口必须保留，否则 CFD 无法定义边界条件。"

**录屏的解法**：在 SimScale 里加两个 `Cylinder`（H80 / R25）与气道 `Union` 合并，
这两个圆柱就是**进出口边界条件的物理载体**（绕 Y 0.17 rad ≈ 9.7°，对应"进气口方向斜向上"）。

**我方要做的是**：在几何阶段就把这两个圆柱加好，并保证接口处有合理的过渡
（录屏的缺陷正是"接口硬接、无倒角、R25mm 相对鼻腔偏大 → 突缩/突扩，
在 18 Pa 小压差下局部损失会污染总压降，而鼻阻力正是由总压降算出的"）。

### 6.2 STL 不含单位 —— 格式固有缺陷

STL 格式**不携带任何单位或坐标系信息**。当前几何尺寸 `32.3 × 80.5 × 32.4`，
SimScale 默认按**米**解释 → 会被当成 32 米。必须：
- 导入时手动指定单位为 mm，或
- 改用 `.obj`（同样无单位，但可用伴随的 `.mtl`/约定），或
- 导出为带单位的格式（STEP/IGES，需 CAD 工具）
