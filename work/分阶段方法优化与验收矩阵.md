# 分阶段方法优化与验收矩阵

更新时间：2026-10-04（北京时间）。当前进度以 [项目主线与实施计划](项目主线与实施计划.md) 为入口；本文件保存步骤、检索依据和验收条件，不另行维护一套项目状态。

本轮目标：逐步优化“匿名 CT → 分割候选 → 粗定位和精调 → 人工审核 → 正式几何 → 网格 → 求解 → 结果”的方法。软件契约通过、真实影像流程通过、医学审核通过和患者 CFD 通过分别记录。当前患者 CFD 结果为 0。

## 3. S01 输入身份与病例冻结

输入：原始文件、匿名病例号、患者分组、选定扫描与软件版本。软件：现有 Python 病例运行器。输出：`case.json`、输入哈希、receipt、候选 revision 及各阶段依赖身份。

| 小步骤 | 优化方法及依据 | 验收或失败条件 |
|---|---|---|
| 01.1 登记扫描和患者分组 | 区分患者、时间点、扫描与上传编号；用 CT 哈希辅助去重（R06、R07） | p3/p3t1 归同一患者；重命名同 CT 不能成为独立参考 |
| 01.2 冻结输入和配置 | 候选绑定 CT、标签、参考库快照和定位代码；后续产物按实际依赖分层 | 输入变化使对应下游失效；不覆盖原五组候选或用户上传病例 |
| 01.3 发布与恢复 | 在独立版本目录生成，检查成功后切换指针；失败保留上一版本及日志 | 重启能读回记录；写入失败、重复启动或过期输入不得宣告新版本完成 |
| 01.4 确认输入边界 | 匿名化在采集/导出侧确认；本地生成编号不能当作完整 DICOM 去标识 | 当前没有完整匿名化验证器；数据对外分享需另行核查，不能仅改文件名 |

当前未知：p0 尚未通过统一病例登记适配；上传匿名编号尚不能自动识别跨上传的同一患者。先使用现有材料登记，不能猜测患者分组。

验收入口：T01、T02、T05。身份变化后重新检查对应候选、审核和几何；不盲目重算无依赖变化的历史结果。

## 4. S02 CT 导入与物理空间

输入：单帧连续 DICOM 序列或确认保留 HU 的 NIfTI。软件：pydicom、SimpleITK。输出：有尺寸、spacing、origin、direction 的 CT 及导入记录。

| 小步骤 | 优化方法及依据 | 验收或失败条件 |
|---|---|---|
| 02.1 分组和物理排序 | 按真实序列及空间位置分组，检查 FrameOfReference；多序列必须选择（R06） | 缺片、位置重复、方向不一致、定位像不进入建模 |
| 02.2 还原强度 | 解码后保留 HU；NIfTI 要求 HU 确认并检查有限值与范围 | 图像“看起来像 CT”不足以证明 HU；没有确认保持阻断 |
| 02.3 保留空间 | 点位、切面、ROI 和掩膜都映射回原始 LPS/mm（R01） | 各向异性/斜置/裁剪原点的前后变换正确；等尺寸不同仿射必须拒绝 |
| 02.4 处理特殊输入 | 多帧、机架倾斜、不均匀层距先明确拒绝，后续单独实现校正 | 不静默归一化或忽略漂移；重采样只作为可验证的工程选择 |

优化选择：不强制把所有 CT 重采样成各向同性；灰度插值和标签插值分别处理，重采样后检查物理位置、局部通道与信息损失。未知为目标医院的特殊导出类型，取得样例后才扩大支持范围。

验收入口：T01、T03 和 R08 的真实输入证据。当前常规输入软件路径可用，不代表全部 CT 格式受支持。

## 5. S03 分割与 QC

输入：有效 CT。软件：现有 TotalSegmentator 任务、SimpleITK/SciPy，必要时使用 Slicer。输出：六类语义标签、空气候选及 QC 报告；修正标签另起版本。

| 小步骤 | 优化方法及依据 | 验收或失败条件 |
|---|---|---|
| 03.1 核查标签与 CT 网格 | 读取每类标签前核对尺寸、spacing、origin、direction（R01、R07） | 错位标签不能索引 CT；必需主气道标签缺失/空值阻断 |
| 03.2 检查原标签强度 | 先测语义标签原 HU，再求空气交集，避免用构造结果验证自身（R07） | 原标签混入组织作为诊断；不能只看阈值后 HU 纯度 |
| 03.3 检查连通和 FOV | 同时报 6/26 邻域、最大连通分量及触边；左右通路分别检查 | 只有边/角相连、不完整 FOV、竞争分量需要复核；不自动填通或删除 |
| 03.4 局部修正与复验 | 在 CT 叠加下用限定区编辑、岛屿和局部平滑（R02） | 保留原标签、修正者及差异；不能用全局平滑掩盖狭缝闭塞或泄漏 |

未知：鼻窦排除掩膜的来源和窦口边界尚未有正式决定；仅有“鼻腔标签不重叠”不能证明排除了鼻窦。15–40 mL 体积范围和左右对称只作提示，不是硬性解剖通过标准。

验收入口：T04；修正后重验 S04–S07。工程完整性通过时报告仍为 `provisional`。

## 6. S04 粗标定与 CT 精调

输入：QC 后 CT/标签、粗定位参考库。软件：现有 UAS 粗定位和本例影像定位脚本。输出：预计点、局部搜索框、精调候选、回退原因及偏移。

| 小步骤 | 优化方法及依据 | 验收或失败条件 |
|---|---|---|
| 04.1 建立解剖坐标 | 由本例硬腭及鼻腔至鼻咽方向建立 UAS，比例用于搜索，物理尺寸保留（R01、R07） | 硬腭拟合/触边/比例不适用时停用粗定位，继续本例影像方法 |
| 04.2 选独立参考 | 排除本人、同 CT 和同病例；重复时间点按患者等权（R07） | 至少两独立参考等条件沿用当前工程预设；参考不足不能制造可信点 |
| 04.3 搜索和回退 | 鼻孔在局部框检查空气证据，失败回到原解剖范围；出口本例重拟合 | 缺影像证据时保留 missing；模板不得覆盖本例异常或强行补点 |
| 04.4 衡量优化收益 | 逐患者留出，比较框覆盖、精调误差、回退和实际人工调整量 | 需独立人工点及法向；16 点到自动候选的 1.72 mm 距离不作医学误差 |

优化选择：当前四位患者继续预训练模型与解剖约束；先收集审核真值和实际耗时，才决定修改 1.5 mm RMS、局部框宽等初始工程限值。不因验证失败放宽阈值。

验收入口：T03、T06；参考库变更只重生成受影响候选，CT 字节不变。

## 7. S05 点位人工审核

输入：当前候选及三向 CT/三维材料。软件：现有网页和 `confirm_landmark_review.py`。输出：点位决定与 `review_config_confirmed.json`。

| 小步骤 | 优化方法及依据 | 验收或失败条件 |
|---|---|---|
| 05.1 按几何影响排优先级 | 先左右鼻孔及鼻咽出口，后左右后鼻孔定位参考 | 三个数值边界缺任一确认不得进入边界建模 |
| 05.2 记录原点与改动 | accept/reject/adjust/undecided 均绑定 proposal 和来源，修改点/法向后检查新图（R06） | 不能用旧静态图代表调整后的真实预览；外部转述只作提示 |
| 05.3 保存并恢复 | 使用已有本例审核接口，校验候选后落盘；重新审核让边界审核 stale | 磁盘可恢复；待定/拒绝保持等待，不能只靠按钮颜色表示通过 |
| 05.4 限定确认范围 | 点位确认决定“在哪里裁”；口腔、鼻窦和最终表面另行检查 | 三点全部接受仍不解锁网格/求解 |

当前缺口：调整后真实预览未生成；p0 审核仍需实际人工决定。现有上传病例保存闭环可复用，不能据此声称 p0 已确认。

验收入口：T02、T05、T07、T08。

## 8. S06 边界审核与预览（当前开发阶段）

输入：当前 CT/标签/候选、完整点位确认件、三个裁剪平面及局部 ROI、保留侧、口腔屏障、鼻窦排除掩膜。软件：边界契约与病例运行器；SimpleITK/VTK 预览生成部分待开发。输出：草稿预览 manifest、六类叠加证据、排除掩膜及独立边界记录。

| 小步骤 | 优化方法及依据 | 实际状态与验收 |
|---|---|---|
| 06.1 固定边界记录 | 三处 opening、LPS/mm、有限向量、非零法向、min/max ROI、保留侧、审核人/时间、口腔及鼻窦判断（R06） | 已实现；缺判断、非法数值和错误单位会拒绝。独立口腔屏障为 wall；共用出口平面需显式引用 |
| 06.2 解析当前身份 | 从 receipt 和点位确认件加载病例/患者/revision、CT/标签/候选/点位审核哈希 | 已实现；不以提交记录自报的哈希充当当前身份 |
| 06.3 生成调整后草稿 | 物理空间重采样三向切片及平面交线；生成 oral/sinus/openings 叠加与裁剪草稿（R01、R03） | 已实现；真实 CT 仍需用目标病例验证，不能把合成影像当作解剖通过 |
| 06.4 绑定全部控制与证据 | parameters_sha256 包含点、法向、ROI、保留侧、口腔模式和鼻窦策略/掩膜；预览 manifest 绑定当前输入 | 已实现；点/法向/保留侧/掩膜改变须生成新草稿，源 CT/气道/掩膜变化会拒绝旧草稿 |
| 06.5 保存与读取审核 | 独立目录原子写入，写后重新核对病例状态与身份再发布；读回重查预览/记录文件 | 已实现；错误/过期输入拒绝、历史保留、restart 可读回，geometry 保持 waiting、患者 CFD=0 |
| 06.6 接工作台与真人检查 | 提供掩膜上传、真实预览接口及查看/保存边界决定；随后核对口腔和全部鼻窦范围 | 已接入 `/boundary-review/` 和对应 HTTP API；尚未取得真实病例医学审核 |

当前组件验收范围：T07/T08 加入物理空间预览、受控掩膜上传和合成影像闭环，验证合同、哈希、状态和渲染；不证明真实鼻腔解剖或医学审核。哈希不证明图像正确或审核人已检查；生产预览只能由受控生成器发布，下一步必须用真实影像验证它。

下一增量的输入：先用已知斜置/各向异性合成体查坐标，再用 p0 副本生成真实草稿。输出：不改变原候选的三向 CT、边界叠加和可追溯 manifest。验收：改点影响正确切片、改法向/保留侧影响相应交线/裁剪、ROI 不误伤其他通道；旧草稿拒绝新参数、失败不切换指针。没有实际人工决定时仍为草稿。

## 9. S07 几何、分区与网格

输入：有效边界记录和对应体素域。软件：SimpleITK/VTK、既有 surface_to_case 与 v1912 snappyHexMesh/checkMesh。输出：四分区闭合表面、几何质量报告、最终表面确认件、体网格及质量报告。
