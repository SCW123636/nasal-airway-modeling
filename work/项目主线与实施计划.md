# 鼻腔建模项目主线与实施计划

更新时间：2026-10-04（北京时间）

## 1. 项目要交付什么

本项目第一阶段的交付目标是：输入匿名化的患者 CT，自动生成一份**可追溯、可人工检查、可进入 CFD 的鼻腔原始气道模型**，完成计算后输出可旋转的三维模型、STL、速度/压力/流线、鼻阻力、左右分流及壁面剪切应力等基础分析。湍流强度按实际采用的湍流模型报告；未计算的指标明确显示未计算。

本计划依据 `资料/鼻腔气流CFD模拟项目需求文档.md`、`资料/需求拓展.txt` 中的阶段一范围，以及现有脚本和产物制定。历史方案中“权重不可用、零分割产出、缺少 VTK”等描述已有后续进展，不能作为当前阻塞。下面的实施项是计划，不是已经完成的功能。

阶段一只回答一个问题：

> 这个患者当前的鼻腔结构和气流是什么样？

结构增删改、虚拟填充、二次模拟和个性化鼻塞设计属于后续阶段。鼻内镜可作为解剖复核的补充资料，首个闭环以已有匿名 CT 为输入。工具选用现有可用的 SimpleITK/TotalSegmentator、VTK 和 OpenFOAM；Slicer 可承接复杂复核或修正，按实际需要调用 Blender，不以经过所有软件界面为交付要求。

## 2. 正确的系统形态

系统采用“自动处理 + 人工检验 + 自动继续”的方式。自动化负责重复、可审计的工作；人工只在解剖边界和异常告警处做决定。人工检验结果必须写成独立记录，绑定到具体 CT、掩膜和几何版本，不能通过网页上的一个“接受”按钮直接改变原始候选或解锁求解。

每个病例都按照以下状态推进：

```text
输入检查
  → 自动分割候选
  → 自动质量门
  → UAS 粗定位预设
  → 本例 CT 精细定位
  → 人工解剖复核
  → 几何与开口生成
  → 几何质量门
  → 患者求解（求解链路已先经过独立非患者验证）
  → 结果质量门
  → 可视化与报告
```

病例运行器负责连接这些阶段、登记输入输出、保留日志、复用内容未变的产物，以及在失败或待人工复核时暂停。复核后从正确阶段继续；输入、审核平面或算法版本发生改变时，相关下游产物失效并重算。非患者算例是求解组件的独立验证，不出现在患者生产数据中。

任何一关失败都保留证据并停在当前病例，不能用参考数据、估计坐标或默认通过替代。当前规模下先完成本地病例运行器和网页操作接口，不先扩建云服务、多用户系统或模型训练平台。

## 3. 人工检验在链路中的位置

统一工作台现在的五步只是入口分组。目标工作台应沿生产线显示输入检查、分割、解剖边界、表面修复、体网格、求解、结果七个阶段，每阶段都能打开真实产物并看到下一动作。现有工具可复用如下：

1. **项目总览**：显示所有病例处于哪一关，以及下一步需要什么；粗定位表显示本例适用性、参考来源、实际局部搜索/回退和粗到精偏移。
2. **候选与三维检查**：看鼻腔主体、左右候选、鼻咽出口和明显泄漏。
3. **切片复核与审核**：逐点看轴向、冠状、矢状切片，记录接受、拒绝或调整；调整只进入审核记录。
4. **意见交叉复核**：把外部人工意见与当前病例 CT 对照，标记可对应、待解释和不采纳，不把转述自动变成移点规则。
5. **计算准入检查**：集中展示入口、出口、口腔排除、鼻窦策略、几何版本、网格质量和 CFD 报告，只有所有必要门通过才允许继续。

坐标和平面关系说明属于辅助内容；它帮助理解图上的十字和虚线，但不应成为人工检验步骤。

同一页面始终保持当前病例和点位：三维点、CT 三向切片和审核表需要联动。调整点或平面后，生成与新位置对应的预览，同时显示原版和草稿版；目前的静态候选图片不能充当调整后已验证的图像。人工还需要看到分割叠加、修复前后差异、入口/出口分区和失败网格的位置。后续开发的重点是这些检查操作及其后端衔接，不能只靠改导航名称来完成。

## 4. 实施顺序

### 阶段 A：冻结输入和状态契约

目标是让每次运行都知道自己处理的是哪份数据、哪一版代码、哪套粗标定参考和哪一个状态。

需要固定：

- DICOM 仿射、LPS 坐标、实际层间距、单位和匿名化检查；
- 原始 CT、语义标签、候选点、审核记录、几何和求解结果的独立哈希；
- `proposed / needs_review / confirmed / rejected / blocked` 等状态含义；
- 患者 CFD 结果默认数量为 0，直到正式人工记录和几何门禁全部满足。

这部分已有数据读取、候选批处理和契约校验可复用；缺少覆盖整个病例的统一运行器和真实阶段状态。先接入已有五组扫描，再完善新匿名 DICOM 的导入，不重新从零开发已有算法。现阶段采用预训练模型和解剖约束，四位患者不足以支撑从零训练并证明一个新模型。

### 阶段 A 的候选子流程：粗标定 → 精细定位

新版 [三轴结构比例粗定位方案](09_coarse_localization/粗定位预设方案.md) 已接入已有批处理和新上传 CT 的候选脚本。分割质量通过后，从硬腭拟合平面和鼻腔至鼻咽方向建立 UAS（患者左、后、上），按左右鼻腔联合范围的 0.5%–99.5% 分位边界映射参考点，再回到本例 LPS/mm 坐标。比例只用于预计点和搜索框，CT 和气道几何保留真实尺寸，候选平面法向由本例影像重新拟合。

正式库 `06_auto_landmarks/reference_library.json` 已登记 p0、p1、p2、p3、p3t1 五组扫描、四位患者；p3 与 p3t1 归为同一患者。每例排除本人、相同 CT 哈希及同病例编号，独立患者等权。p2 已按粗定位专用接受记录登记为带质量警告的参考；它自身作为目标病例时，硬腭拟合 RMS=1.832 mm 超过 1.5 mm 初始工程限值，仍不启用粗定位。至少两位独立参考患者、比例和参考分歧满足工程条件时，鼻孔在粗定位框内做空气射线搜索；失败则回退原解剖范围。后鼻孔和出口仍按本例标签空气接触面拟合，再与预设对照。参考不足或不适用时继续本例影像定位，影像无证据时保留点位缺失。

每例保留 `coarse_localization.json` 和 `coarse_adjustment.json`，包含参考来源、LPS/UAS/UAS-NORM 坐标、搜索框和粗到精偏移；参考库哈希进入候选输入身份，库变化使批处理缓存失效。工作台总览显示本例适用性、局部搜索/回退和偏移，上传病例状态接口与工作台数据也携带同一摘要。UAS-NORM 是比例坐标；它不能替代真实毫米单位参与几何或 CFD。

`coarse_reference_acceptance.json` 只登记粗定位参考接受；正式审核仍需生成与当前 CT、标签、候选及几何绑定的确认记录。当前 16 点探索回测的 1.72 mm 中位距离是到已有自动候选的距离，不能写成医学误差。验收需新增逐患者留出的独立人工真值，记录粗定位误差、搜索框漏检、精调偏移、回退比例及实际人工调整量。

### 阶段 B：完成一个病例的人工复核闭环

优先选 p0 作为工作台和流程的首个完整病例，因为它是各向同性扫描，数据条件最清楚。先完成可以自动运行到“待人工复核”的闭环，并验证人工输入的保存、校验和恢复。没有实际审核决定时保持待复核，不把流程演练记作解剖确认。

审核记录至少要覆盖：

- 左右鼻孔入口；
- 鼻咽出口；
- 左右后鼻孔作为定位参考；
- 口腔排除是否已单独确认；
- 鼻窦边界策略是否明确；
- 审核人、时间、输入哈希和被审核几何哈希。

`confirm_landmark_review.py` 已提供审核导出到确认件的转换基础，后续需要验证并接入实际病例运行器。候选平面审核用于生成新几何；生成和修复后的最终几何需要另行复验与哈希绑定。旧几何的确认不能自动继承到发生变化的新表面。复杂分割修正可调用 Slicer，并将修正结果重新纳入同一版本链。

对于鼻孔入口“略深”、后鼻孔“偏后/偏上”、鼻咽出口靠近软腭等意见，系统只生成待检查提示，不根据文字转述自动移动坐标。

### 阶段 C：从标签和审核记录生成正式几何

阶段一主版本采用**鼻腔主气道、排除口腔和鼻窦**的口径。先把这一版本实现并验证；保留鼻窦的 `G_sinus` 是后续敏感性研究，不作为首个主闭环的必做版本。不能只凭语义标签没有重叠，就宣称窦口和口腔边界正确。

将候选体素、入口/出口平面、口腔屏障和已确认的鼻窦排除策略组合成带语义分区的表面。必须保留：

- `nostril_L`、`nostril_R` 入口；
- `nasopharynx` 出口；
- `wall` 壁面；
- 鼻窦排除边界和核查结果；如果不确定性会影响计算域且未解决，则停在待复核。

几何生成同时输出体积、连通性、孔洞、非流形边、法向和来源哈希。供体网格生成的流体边界须几何闭合，并将入口、出口端面保留为独立分区；不能把端面当成 wall，也不能全局封洞后丢失开口语义。修复和重采样要保留鼻阀、鼻甲细间隙等关键通道，并量化处理前后差异。展示用减面表面不能直接当 CFD 表面。

### 阶段 D：先修好非患者 CFD 闭环

在患者求解之前，必须让表面到求解的合成圆管链路严格通过。当前入口剖面修正和加长管道诊断改善了部分误差，但两个诊断仍失败，且 `checkMesh` 有 concave cells；这些对照尚不能唯一确定误差原因。

下一步按这个顺序排查：

1. 使用几何质量通过的圆管网格，先排除 concave cells；
2. 用充分发展的入口或更长入口段做受控比较；
3. 在同一出口/入口定义下复核面积、半径、流量和压力单位；
4. 重新跑粗、中、细三档，并保留每次日志和来源哈希；
5. 只有压降、守恒、收敛、峰值速度和网格质量同时通过，才把 S1→S2→S3→S4 标成可用。

严格失败报告继续保留，不能调宽阈值或覆盖为通过。

### 阶段 E：完成自然分流适配，再做患者首例

患者 CFD 的首例应是 p0，且必须满足：

- 正式人工记录已经确认三处边界；
- 口腔排除和鼻窦策略有独立确认；
- 患者几何不是 provisional；
- 入口、出口、壁面分区完整；
- 体网格 `checkMesh` 通过；
- 层流基线先通过，SST 作为独立敏感性工况；
- 15 L/min、出口 0 Pa 的主工况与 18 Pa 压力驱动工况分开记录。

主工况沿用现有契约：双鼻孔共用可调静压、鼻咽出口 0 Pa，外层调节共同入口压力，使总吸气流量达到 15 L/min；左右分流由几何阻力决定。该适配器当前尚未实现，先用有不同支路阻力的非患者几何验证控制和分流，再接患者。现有表面到 case 脚本的左右等分入口只属于人为对照，不能直接用于报告患者自然分流。

首例还要完成相同几何和边界下的网格细化、守恒与结果稳定性检查，再用于对比。已有人工 STL 只有在扫描对应关系、单位、边界协议和来源确认后才能作为参考；没有这些条件时不填 Dice、定位准确率或临床准确性。p1、p2、p3、p3t1 在首例链路稳定后再批量进入，p3 的两个时点不当成两位独立患者。

### 阶段 F：结果展示和批量运行

结果页展示实际数值字段：速度、静压、流线、湍流强度状态、鼻阻力、左右流量、壁面剪切应力和质量检查。层流没有物理意义上的湍流强度时，显示“无湍流模型/不适用”，不能填 0%。壁面剪切应力需实际导出相应场，未导出时显示未计算。每个患者结果都能追溯到输入、几何、网格、求解参数和日志，并能下载模型、计算文件和基础报告。

细化后的首个开发增量“点位审核 → 鼻窦掩膜上传 → 调整后 CT/平面预览 → 独立口腔及鼻窦范围审核记录”已经实现并通过合成影像闭环；下一步用真实病例生成草稿，再完成四分区闭合表面及最终复验。求解组件先修严格圆管和共同静压反馈，在等待解剖复核时可继续。

近期按以下顺序推进，并在每项完成后更新本文件和统一工作台状态：

1. **补齐项目语义标签**：为 NasalSeg 130 例补充 `oropharynx`、`hard_palate`、`soft_palate` 的可靠标注，或切换到包含这三类结构的分割输入，再重跑 S03 QC；
2. **病例运行器和任务页**：把已验证的 P001–P130 身份、CT 和标签产物接入统一运行器，先让一个病例自动走到准确的待复核位置；
3. **有效人工检查**：在工作台中完成病例/点位联动、CT 和三维对照、调整后预览、口腔和鼻窦边界检查、审核保存和导出；当前网页和后端入口已就绪，仍需真实病例操作；
4. **审核到新几何**：演练记录校验、裁剪/修复、分区和新版本复验；未审核产物仍标候选，确认记录绑定最终几何；
5. **求解组件验收**：修复圆管网格质量与压降，独立验证共同入口压力反馈和自然分流。工程验证可在等待人工复核期间进行；
6. **患者首例**：实际审核和工程门禁均满足后，执行 p0 的体网格、主工况、网格细化和结果质量检查；
7. **完整交付和多例复跑**：输出可视化、STL、计算文件和指标报告，再扩展到其余扫描并记录失败类型和实际人工操作量。

第一项的验收是“一个病例能自动走到准确的待复核位置”，不是页面按钮变成可点击。第三项的软件验收是“合成影像和受控接口能生成可复验的新版本，错误或过期输入会被拒绝”，真实病例验收仍要求人工检查。工程与患者结果都要以真实产物验收，单元测试数量和页面检查通过不代表整项目完成。

## 7. 项目判断标准

项目成功的标准是：同一个病例能够从匿名 CT 一路追溯到实际气流结果，人工只在必要解剖判断处介入，审核后能够自动接续；失败能停在正确位置，结果能重复生成，模型、计算文件和报告能够导出。现阶段仍处于候选复核和求解组件验证，没有完成这个最终闭环。
