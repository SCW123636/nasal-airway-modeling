## 项目一句话背景

把**鼻腔 CT** 做成可用于 **CFD 气流仿真**的干净几何与网格。
链路：DICOM → TotalSegmentator 分割 → 自动解剖点位提案 → marching cubes 建表面 →
开口平面自动定位 → 体网格 → OpenFOAM 求解。

规模：27 例副鼻窦 CT（b01–b27）+ 5 例试点（p0–p3t1，含双时点）。
交付目标：**网页端可交互 3D + 流速/压力/湍流强度三维度**。

工程纪律（重要，请勿建议放宽）：**所有主张必须有实测证据与可复现命令；判据不得拟合；
不明处显式标"未实现"，不得含糊称为"已完成"。**

### A1 ⭐ 鼻咽出口平面的"种子"机制依赖手工 ROI 盒 —— 当前最大阻塞

**现象**：b01–b24 全批中 6 例升级，其中 **4 例集中在 `nasopharynx_outlet`**
（b04 / b15 / b18 / b23），报 `seed_lost`；b04 / b23 同时报 `onset_outlier`
（onset 偏离观察带 [−4, +1] mm 达 −7.25 / −5.00 mm）。另 2 例为 `nostril_L seed_lost`（b04 / b05）。

**机制**（`work/lib/connectivity_opened_surface.py::flood_mask`，第 42–62 行）：

```python
seeds = negative & ((points >= lo) & (points <= hi)).all(axis=1)   # 负侧顶点 ∩ ROI 盒
if not seeds.any(): raise ValueError('no negative-side seed inside the reviewed ROI')
```

即：**要求同时满足「在平面负侧」和「落在 ROI 盒内」**。ROI 盒随平面沿法向平移
（`auto_opening_pipeline.py:70-75`）。失败 = 平面移到新位置后，盒内没有任何负侧顶点。

**已实测并排除的解释**：

| 假设 | 检验 | 结果 |
|---|---|---|
| ROI 盒太小 | 24 例 × 3 开口的最小边长 vs 逐开口成败 | **完全重叠，零区分力**（出口：失败 4.0/5.2/5.9/5.9，通过 4.6–10.2）。b02 出口 min_ext=4.6 通过，b04 出口 4.0 失败 |
| ROI 平移是问题 | p0 专项探针：ROI 不动只移平面，5 个 delta | 全败（`p0_roi_translation_probe.py`） |
| 手抄裁切出错 | 改用生产函数二分定位 | 已排除（`p0_orphan_probe.py`） |

**为什么这条重要**：ROI 盒是**试点 5 例手工调出来的产物**，被当成了通用机制。
它承担了两个本不该合并的职责：① 判定保留哪个连通分量（语义）；② 提供搜索种子（数值）。
只要几何一换、平面一动，②就会随机失效。

**什么样的回答有用**：
- 是否有**不依赖手工盒**的种子方案？候选方向（请评估可行性并给出具体做法）：
  从开口中心沿平面法向**向内射线**取首个表面交点作为种子；用**测地距离**从最近开口出发；
  用**截面环**（已有 `section_loops` 生产件，由边-平面交点构造）确定负侧内部点。
- 出口平面为何系统性弱于鼻孔？出口附近是否本来就有解剖歧义（软腭/口咽交界）？

**相关文件**：`work/lib/connectivity_opened_surface.py`、`work/lib/auto_opening_pipeline.py`、
`work/07_cfd_pipeline/正常路径验收报告_b01-b24_20261012.md`

### A2 ⭐ 「扫描截断」判据把必要条件当成了充分条件

**现象**：b01–b24 首跑 **auto_pass 仅 2/24**，22 例全部同因 `no_planes`。

**根因**（`work/lib/auto_anatomy_landmarks.py:433`）：

```python
truncated[name] = bool(np.any(c.min(0)==0) or np.any(c.max(0)==np.asarray(m.shape)-1))
```

即「标签掩膜**任一体素触及 CT 立体六面之一**」即判为 truncated；
第 468 行据此把 `nasopharynx_outlet` 从 `proposed` 降为 `needs_review`，下游当硬阻塞。

**已实测**（24 例）：

| 指标 | 值 | 解读 |
|---|---|---|
| `oropharynx` 触边 | **24/24** | 口咽本就向下延伸出扫描范围 → 判据恒真 |
| `soft_palate` 触边 | **22/24** | **全部触头侧（superior）面** —— 颈部长度扫描里软腭就在 FOV 上界 |
| 未触边 | b01 / b11 | **恰好就是通过的那两例** |

点位质量**零影响**：24/24 点位全存在；平面拟合 RMS 0.00–0.41 mm；
到软腭距离 4.95–11.68 mm —— 与 2 个 `proposed`（5.74 / 6.43 mm）**分布完全重叠、无区分力**。

**已处置（但不彻底）**：加了显式开关 `--allow-needs-review`（默认关，被放行者记入
`admitted_needs_review`），全批 2/24 → **18/24**。**判据本身未修**。

**什么样的回答有用**：
- 「扫描是否真的把某个解剖结构切断了」应当**如何判定**才既有意义又稳健？
  我们的想法：判据必须回答「**结构在扫描边界外是否还有延续**」，而非「标签碰没碰到体素边界」。
  请给出可实施的定义（例如：沿该结构主轴检查是否在边界处**非自然终止**；
  或检查该结构在边界面的**截面是否与体内典型截面同量级**）。
- 对颈部 CT 而言，"软腭触 FOV 上界"是否是**正常解剖表现**？请给出解剖学依据
  （我们倾向于是，但需要文献支撑才能写进对外材料）。

### A3 ⭐ CFD 前置的体网格：最优候选 Netgen 仍差 1 项

**现状**：患者 CFD **至今为 0**（8 份配置 `execution_allowed` 全 false）。
已实测对照 6 种网格路线（`work/07_cfd_pipeline/网格软件实测比较.md`）：

| 网格器 | 结果 |
|---|---|
| `snappyHexMesh`（原生） | 7920 concave cells、10 凹面 → fail；调参无效（`nSmoothPatch=0`→8320，收紧 `maxConcave`→9408 且 48 非法面） |
| Gmsh | 消除 concave，但 70 个小行列式单元 + 7 低插值权重面；细化后 106/5，均 fail |
| TetGen `-pq1.2a0.03` | concave/插值/几何通过，但 2059 小行列式单元 |
| **Netgen `maxh=0.4, grading=0.1`** | **当前最佳**：26,887 四面体，三边界语义保留，concave/非正交/偏斜/插值/体积比**全通过**，仍有 **8 个小行列式单元 → `checkMesh` 失败 1 项** |
| `polyDualMesh` | 排除（max skewness 648.84、2536 concave） |

**注意**：`maxh=0.2` 反而恶化到 25 个小行列式单元（非单调）。

**什么样的回答有用**：
- 小行列式单元（small determinant）的**成因**与**针对性修复**：是表面 sliver 传入，
  还是体积网格器在该尺度下的固有行为？Netgen 是否有对应参数（如 `optsteps`、
  `elperr`、局部细化）？**为什么细化反而变差**？
- 对于**鼻腔这种薄壁、狭窄、各向异性**的解剖腔，体网格的**工程最佳实践**是什么？
  （边界层？六面体主导？polyhedral？请给可落地做法与文献）
- 若 Netgen 的 8 个单元确实无法消除：这在 CFD 实务中是否**可接受**？
  行业通常的 `checkMesh` 容忍度是多少？（我们不敢自行放宽，需要依据）

### A4 ⭐ 表面自相交门禁对 marching cubes 输出是否适用

**已确定事实**（不依赖自研判据）：
- native OpenFOAM `surfaceCheck` 在**未裁切的干净 MC 原始面**上也报：
  `p2_source` / `p3t1_source` 最短边 0.32 / 0.33 mm、最差质量 0.57、**全闭合流形**、
  最大边仅 0.68 mm，仍报 **117 / 179 个点**。sliver 修复后 p2 117→115、**p3t1 179→194（恶化）**。
- 报点 **100% 落在 `wall` patch**、**不成簇**（p2 68 簇/47 孤立，最大簇 9–25），
  到最近三角形距离中位数 1.7–1.9e-4 m（**远大于** 1e-6 m 容差）。
- 本项目**自研的三套自相交判据全部被证伪**（见 D 区），结论是**批大小决定结论**，不可信。

**已处置**：native 自相交**降级为 advisory 记录项**（`work/lib/surface_gate.py`），
改用四条替代门禁（更难通过，非放宽）：`mesh_watertight` / `volume_conserved` /
`openings_are_open`（≥10 mm²）/ `patch_areas_stable`（≤2%）。

**什么样的回答有用**：
- **根本问题**：native `surfaceCheck` 报的是**点**不是面片对。它在 MC 网格上报出的这些点，
  是**真穿插**还是**掠接触/容差伪命中**？请给出可判定的做法。
- 若需要**可信计数**：用成熟库（CGAL / libigl / trimesh+meshfix）的**具体调用方式**与
  **精度陷阱**（我们已知踩过 `abs(det)>=1e-9` 阈值量纲错误，
  det 单位 m³、典型值 ~8e-11）。
- **是否需要**在意？还是说 MC 输出在 0.2–0.35 mm 网格尺度上的这类报点是**已知固有现象**、
  对 CFD 无实质影响？请给文献或行业依据。

### A5 入口/出口边界条件：18 Pa 的物理含义仍未定

**已确定**：★ **18 Pa 已溯源 = SimScale 出口端 gauge 静压 +18 Pa，严格不是 Δp**
（= **0.18355 cmH₂O**，历史记录写成 1.8 cmH₂O 差一个数量级，已修正）。

**已实测**：固定流量 + 常物性不可压缩下，仅改出口压力参考常数 → 压力场整体平移
（入口面平均静压 0.215879249155 → 18.215879249160 Pa），**压降不变**（0.215879249155
vs 0.215879249160 Pa），偏离均匀平移最大 9.96e-11 Pa。
→「定流量 + 18 Pa **一定过约束**」**不成立**。

**未实现**：主工况需要的 **`common_inlet_pressure_feedback`**
（两鼻孔共用可调静压 + 出口 0 Pa + 外层调压使总流量达 15 L/min，左右分流由几何自然分配）
**尚未实现**。当前 8 份配置全部 `execution_allowed=false`，门禁要求
`review.status=confirmed` + `method=human`。

**什么样的回答有用**：
- 鼻腔 CFD 的**入口条件**文献最佳实践：定流量 vs 定压力 vs 生理波形？
  单鼻孔 vs 双侧？**左右自然分流**在实务中如何施加（是否有标准做法）？
- 出口条件（鼻咽/喉端）设定为 0 Pa 表压的**合理性边界**在哪里？
- **Re ≈ 5276 时应选层流还是 SST？** 鼻腔的转捩/湍流在文献中如何处理？
  湍流强度应如何报告（无量纲比值 → 百分数）？

**相关文件**：`work/07_cfd_pipeline/18Pa与边界条件修订.md`、`work/07_cfd_pipeline/CFD配置与结果契约.md`

### B2 开口面积目标值的解剖学依据

**当前判据**：沿平面法向二分，直到**生产 `clip_and_cap` 实际产出的端盖面积**达解剖目标。
