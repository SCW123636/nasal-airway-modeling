# 体网格软件实测比较与推荐

更新时间：2026-10-05（北京时间）

## 判断标准

本比较使用同一份非患者圆管 STL（毫米坐标，inlet/outlet/wall 三个语义面），导入 OpenFOAM v1912 后运行 `checkMesh -allGeometry -allTopology`。以下门禁沿用项目 CFD 契约：不能有凹单元、负或零体积、错误方向面、小行列式单元、低插值权重面、严重非正交或超限偏斜。网格生成成功、软件能打开 STL、求解器能结束，都不算通过。

原始 `snappyHexMesh` 失败报告仍保留在 `solver_reference/phantom_validation/validation.json`，其 `verdict` 仍为 `fail`；患者 CFD 结果仍为 0。

### 已验证的修复路线

OpenFOAM v1912 的 `cell determinant` 只使用内部/耦合面向量；只有两个外边界面的四面体只剩两个内部面，面积张量秩不足，determinant 按定义为 0（无内部面时源码还会显式置 0），因此触发 `minDeterminant` 门。该现象不是把阈值放宽就能合理消除的。实验脚本 [`repair_boundary_tetrahedra.py`](../lib/repair_boundary_tetrahedra.py) 只对这类单元增加一个几何中心点并分成四个四面体：

- 外表面三角形先与四面体真实外边界逐一核对，重复表面面会拒绝转换；inlet/outlet/wall 标签不重建、不删除。
- 4 个目标单元变为 16 个，体单元从 26,096 增至 26,108；原表面点坐标保持不变。
- 体积从 `4.873106642203134e-7 m³` 变为 `4.873106642203135e-7 m³`，相对变化 `2.2e-16`。
- OpenFOAM `checkMesh -allGeometry -allTopology`：`Mesh OK`；最小 determinant `0.0073794`，最大非正交 `46.77°`，最大偏斜 `0.625`，最小插值权重 `0.1677`。
- 同一修复网格用 OpenFOAM v1912 `icoFoam` 实跑至 `t=0.0005`（50 步）正常结束；最大 Courant `0.2374`，末步累计连续性误差约 `4.27e-12`。这只是解析圆管的数值链路复核，不是患者物理结果。

这条路线解决的是体网格拓扑门失败，不能修复患者 STL 的自交、错误入口位置、解剖边界或模型选择。患者表面必须先由 Slicer/Blender 完成边界审核，再用 Netgen 生成体网格、执行相同局部细分和本地 OpenFOAM 门禁。

## 资料依据

- OpenFOAM 官方 `snappyHexMesh` 文档：[snappyHexMesh](https://doc.openfoam.com/2312/tools/pre-processing/mesh/generation/snappyhexmesh/)。本机 v1912 的实际行为以 `checkMesh` 和日志为准。
- Gmsh 官方手册和 t13 教程：[Gmsh manual](https://gmsh.info/doc/texinfo/gmsh.html)，说明 STL 重网格流程是 `Merge → ClassifySurfaces → CreateGeometry → Surface Loop → Volume`；手册同时提醒，离散表面重网格更适合成像类密集 STL，面质很差或为节省尺寸生成的 STL 不一定适合直接重网格。本文保存的资料：`C:/ts_work/mesh_tools/gmsh_current_manual.html`。
- Gmsh 官方手册列出 3D Delaunay、Frontal（Netgen）和 HXT 等算法，并说明 Delaunay 是稳健的默认 3D 算法；本机 4.8.4 的 Frontal 需要 Netgen，HXT 实验没有形成有效网格。
- TetGen 官方页面：[TetGen](https://wias-berlin.de/software/tetgen/)，用于核对 PLC、质量约束和边界 marker 语义；本机实际使用的是 Ubuntu 22.04 的 TetGen 1.5 包。
- Netgen 官方项目：[Netgen](https://github.com/NGSolve/netgen)，本机通过 Python 绑定生成并转换网格；仍以 OpenFOAM 门禁作最终判断。
- SimScale 官方 Standard Mesher 文档说明其有限体积网格器可生成四面体或六面体三维非结构网格，并提供曲率、表面尺寸、间隙和边界层控制。资料：`C:/ts_work/mesh_tools/simscale_meshing.html`。本机没有账号/API，也没有实际上传和导出网格，因此不能把它写成已验证方案。
- CF-MESH+ 官方页面显示为商业产品并提供试用；本机没有安装包，没有实测证据，不能作为当前推荐。资料：`C:/ts_work/mesh_tools/cfmesh_home.html`。

## 推荐决策

当前推荐顺序是：

1. **先保留 OpenFOAM `snappyHexMesh` 作为生产门禁和求解器**，但不再继续凭参数小调期待它自动修复这类凹面；当前原生路线应回到几何表面质量、开口封面和背景网格拓扑重新处理。
2. **采用 Netgen + 局部边界四面体细分作为当前首选开源路线**。它在同一 STL 上先生成质量最接近门禁的网格，再用可追溯的拓扑修复消除双边界面单元；外表面、体积和 patch 语义均有独立检查。患者表面仍必须重新复验，修复脚本不能绕过任何 `checkMesh` 门。
3. **Gmsh 作为可复现的第二候选**，适合表面分类、物理组和批处理；当前 2 项质量失败，不能直接喂给患者求解。
4. **SimScale/CF-MESH+ 只能作为外部或商业后备路线**。若使用，必须导出网格、在本地运行相同 `checkMesh`，并检查 inlet/outlet/wall 语义、单位、体积和守恒；SimScale 社区项目的患者隐私和公开性也必须先解决。

正式患者流程的解除条件仍是：通过医学边界审核、用当前患者几何生成带语义体网格、`checkMesh` 全部通过、再完成解析/网格独立性和求解门禁。任何候选软件在这些条件满足前都不能解锁患者 CFD。

### 软件选择的更新

本机已经有 **3D Slicer 5.12.4**。官方文档明确支持：Segment Editor 的阈值、区域生长、Scissors 和 Logical operators；Segmentations 模块在 binary labelmap、closed surface 和模型格式间转换并导出 STL/OBJ；Surface Toolbox 提供清理、重网格、减面、平滑和填洞。它适合把当前 provisional 候选与 CT、语义标签和三端 Markups 平面放在同一坐标系中，由人工确认后再导出新几何：

- [3D Slicer Image Segmentation](https://slicer.readthedocs.io/en/latest/user_guide/image_segmentation.html)
- [Segment Editor](https://slicer.readthedocs.io/en/latest/user_guide/modules/segmenteditor.html)
- [Segmentations](https://slicer.readthedocs.io/en/latest/user_guide/modules/segmentations.html)
- [Surface Toolbox](https://slicer.readthedocs.io/en/latest/user_guide/modules/surfacetoolbox.html)

Slicer 的官方总览还列出 SegmentMesher 扩展可以从分割生成四面体体网格，但本机没有把该扩展作为生产工具实测；即使采用它，也必须导出网格后在本地运行同一套边界语义、体积和 OpenFOAM `checkMesh` 门禁。SimVascular 官方 TetGen 文档同样要求封闭/无自交的实体模型，并把开面、自交和很小特征列为 TetGen 失败原因；它可作为外部备选，不改变当前主路线：[SimVascular TetGen meshing](https://simvascular.github.io/documentation/meshing.html)。

当前实际推荐保持为：**3D Slicer 完成医学边界审核和几何导出 → Netgen 体网格 → 只对已证明的双边界面四面体做局部修复 → OpenFOAM `checkMesh` 和求解器门禁**。Blender 只保留为表面可视化/检查工具，不再把它导出的闭合旧 STL 当生产几何。

## 复现入口

Netgen 实验使用 `C:/ts_work/mesh_tools/gmsh_trial/netgen_stl_to_msh.py`，生成 MSH 后由 `gmshToFoam` 转换；OpenFOAM 质量检查命令为：

```bash
source /usr/share/openfoam/etc/bashrc
gmshToFoam netgen_tube_g01.msh
checkMesh -allGeometry -allTopology
```

局部修复的复现入口为 `work/lib/repair_boundary_tetrahedra.py`；它依赖 `meshio`/`numpy`，输入必须是带 Gmsh 物理标签的线性四面体网格：

```bash
python repair_boundary_tetrahedra.py netgen_tube_g0075.msh netgen_boundary_repaired.msh
gmshToFoam netgen_boundary_repaired.msh
checkMesh -allGeometry -allTopology
```

官方资料仍作为算法语义依据，实际准入以本机 OpenFOAM v1912 日志为准： [OpenFOAM checkMesh 源码](https://develop.openfoam.com/Development/openfoam/-/blob/OpenFOAM-v1912/src/OpenFOAM/meshes/primitiveMesh/primitiveMeshCheck/primitiveMeshTools.C)、[Gmsh 手册](https://gmsh.info/doc/texinfo/gmsh.html)、[Netgen 官方项目](https://github.com/NGSolve/netgen)、[CGAL Mesh_3](https://doc.cgal.org/latest/Mesh_3/)。

## 2026-10-06 Netgen VOL 转换入口实测

在同一隔离圆管 VOL 上实测了新增的 `work/lib/netgen_vol_to_msh.py`。Netgen 6.2 读取 `netgen_tube.vol` 得到 2,045 个点、10,024 个四面体和 descriptor 1/2/3 的 38/38/1080 个表面三角形。转换命令要求显式指定单位、profile 和 descriptor 映射，不从面顺序推断 inlet/outlet/wall；报告保留 source、mapping 和 output SHA-256，并明确 `patient_solver_allowed=false`。

实测证据位于 `C:/ts_work/mesh_tools/gmsh_trial/` 的 `netgen_tube_converted_20261006.conversion.json`、`netgen_tube_converted_repaired_20261006.repair.json`、`foam_converted_repaired_20261006/checkMesh.log` 和 `foam_converted_repaired_solver_20261006/solver.log`。这些是解析圆管隔离结果；它们不能证明患者几何已绑定、医学边界已确认或患者 CFD 可以运行。
