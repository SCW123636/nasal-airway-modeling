## 二、更正：上午「真相交 = 0」为什么错

### 2.1 量纲错误（根因）
`decide_selfintersection_precision.py` 里判据是 `valid = abs(det) >= eps`，`eps = 1e-9`。
但 `det = -d·(e1×e2)` 是 **长度×面积，单位 m³**。本例典型值：
边 4.6e-4 m ×（2×面积 ≈ 1.8e-7 m²）≈ **8e-11**，比 1e-9 小一到两个数量级。
→ 该阈值把**几乎全部真实相交都判成"退化/无效"**而丢弃，于是"0 真相交"是判据造出来的，不是测出来的。

### 2.2 打印口径误读（差点据此下第二个错结论）
我一度把**未归一化的点积** `n·(P−Q0)`（≈5e-11，单位 m³）当成距离。
除以 `|n| ≈ 1.8e-7` 后，真实平面间距是 **0.15–0.44 mm**，与网格尺寸同量级——这些是彼此靠近的三角形，并不是共面。

### 2.3 修正后的判据仍然不可信（关键）
新核 `work/lib/tri_tri_exact.py`：归一化 `|det| ≥ eps_rel·|d|·|n|`，共面单独投影到 2D 判重叠，8/8 自检通过。
但对 **p2_source 同一批 561405 个候选对**：
- 一次性算 → **39** 个命中
- 分块算（16000/块）→ **1176** 个命中
- 逐元素不一致 **1165** 处

定位到具体对（如 triangle 540 vs 598）：掠接触下重心坐标 `u ≈ 1.1` 正落在 `[0,1]` 边界，
`np.einsum` 的求和次序随数组长度变化 → 舍入不同 → **批大小决定结论**。
→ **该判据在掠接触上数值不稳定，39 与 1176 两个数字都不可信。**

### 2.4 第三次尝试也失败（记录在案，避免重犯）
`work/lib/surface_contact_audit.py` 改用数值稳定的「平面分侧检验」，得到 285884/566662 = **50%** "真穿插"。
错因：把**必要条件当充分条件**——两个相距约等于自身尺寸的三角形，随机朝向下互相跨平面本就是常态，跨平面不蕴含相交。

## 四、被推翻的原文（仅供追溯，勿引用）

**方法**：`decide_selfintersection_precision.py`，取 native 命中三角的 2 mm 邻域，
float64 / float32 双精度对照，宽松 1e-12 与严格 1e-9 两种容差。

**结果**：p2 native 115 → 严格容差 float64/float32 均 **0/0**；p3t1 native 194 → **0/0**。
宽松容差下的命中逐对复算全为边界伪命中（t/u/v 越界或边两端同侧）。

**结论（已废止）**：native 命中不是真穿插，是裁切 sliver 导致的伪命中；
「表面自相交」与「短边/瘦三角形」同一根因，局部重三角化可一次过两道门。

## 六、二次更正（2026-10-12）：§5.3 的距离证据与 §三.3 的 75/111 **均无效**

> 由云端外部调研质疑触发，本地复测定论。**门禁降级的决定不变**，但下面两条支撑证据作废，
> 依据整体更换。完整核验见 `work/07_cfd_pipeline/外部调研核验结论_20261012.md`。

### 6.1 「报点到最近三角形距离 1.7–1.9e-4 m」测错了对象

`work/lib/locate_native_hits.py:42-45` 建的是**三角形重心**的 KD 树，量的是到重心的距离：

```python
centres = verts[tris].mean(axis=1)     # 重心
tree = cKDTree(centres); d, i = tree.query(pts)
```

重心在三角形**内部**，所以该距离只是"到三角形距离"的**上界**：一个正好落在三角形上的点，
照样测出约三角形内切半径的量（0.1–0.2 mm）。
单点暴力对账（p2_source#0，220,812 个三角形全量）：真实最近三角形距离 **8.06e-10 m**，
旧指标报 **1.697e-04 m** —— 差的正是"到重心"那一段。→ §5.3 该条推论不成立。

### 6.2 干净重测（`work/lib/remeasure_native_hit_distance.py`，8/8 自检 + 暴力对账一致）

| case | 报点数 | 真实最近三角形距离 min/median/max | ≤1e-9 m | ≤1e-6 m | ≥2 非相邻三角形 |
|---|---|---|---|---|---|
| p2_source | 117 | 0 / 1.39e-8 / 3.42e-7 | 31 | **117** | **0** |
| p2_repaired | 115 | 0 / 1.58e-8 / 3.42e-7 | 29 | 115 | **0** |
| p3t1_source | 179 | 0 / 2.35e-7 / 4.42e-7 | 9 | **179** | **0** |
| p3t1_repaired | 194 | 0 / 2.17e-7 / 4.43e-7 | 9 | 194 | **0** |

→ **全部报点都在表面上**（≤0.44 µm，即 STL ASCII 量化尺度），但**没有一个是两个非相邻三角形的真交点**；
单点探针显示第二近三角形与最近者**共享一条边（相邻）**。
**修正后结论**：native 报点是**边缘-三角形邻近命中**，不是真穿插
—— 方向与 §5.3 一致，但依据已整体更换。

### 6.3 §三.3 的「75/117 与 111/179 落在两个互不相邻三角形上」同样作废

`adjudicate_native_hits.py` 的内点投影分支 `d_plane = |n|·clip(n·ap/|n|², 0, 1)`
量纲是 **m²**（数值 ≈ 2×三角形面积），却与 1e-9 **m** 阈值直接比较；
且 clip 到 [0,1] 会把法向朝背离方向的三角形全抹成 0。
实测：对单个报点，旧公式把 **133,859 / 220,812** 个三角形判成"距离 0"。
另有"精确命中不足 2 个就退化为取最近两个三角形"的 fallback。→ 该计数不可用。
