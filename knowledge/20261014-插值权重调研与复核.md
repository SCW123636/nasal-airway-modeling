## 一、判据是什么（源码有据）

`checkMesh -allGeometry` 报的 `Face interpolation weight` = 面心插值权重：

- 定义式 **`min(dNei, dOwn) / (dNei + dOwn)`**（`polyMeshGeometry.C:1173-1178`）——
  即「面心沿法向到两侧体心的投影距离之比」，测的是**面心是否过分偏向某一侧单元**。
- 阈值 **0.05 硬编码**在调用处（`checkGeometry.C:905`），`-allGeometry` 下**用户改不了**。
- 与并列的 `Face volume ratio`（阈值 0.01，`checkGeometry.C:926`）是**两个独立的面级检查**，
  算法互不相干（一个看距离投影比，一个看相邻单元体积比），**不能互推**。
- **判据只返回 bool，不抛 FatalError** → **它本身不会让 simpleFoam 崩**（线性组合 + `VSMALL` 防除零）。

## 二、⭐ 主对话复核：T-005 的「串档嫌疑」**不成立**，但观察是真的

T-005 发现：两版修复网格的 min weight 都是 `0.0117811599686`，而面/单元计数不同（114/585 vs 106/494），
怀疑日志串档。**主对话逐行核对三份日志，结论：不是串档，是"最小值真的相同"。**

| 指标 | `checkMesh.log`（maxh=1.0 修复） | `checkMesh_maxh04_repaired.log`（maxh=0.4 修复） | 是否相同 |
|---|---|---|---|
| points | 229,033 | 377,180 | ✗ |
| faces | 2,378,797 | 4,112,415 | ✗ |
| cells | 1,161,194 | 2,028,003 | ✗ |
| Mesh non-orthogonality Max | 87.3238242586 | 87.354399658 | ✗ |
| min cellDeterminant | 1.11163982652e-07 | 1.80188985973e-07 | ✗ |
| `<0.001` 单元 | 585 | 494 | ✗ |
| 严重非正交面 (>70°) | 204 | 198 | ✗ |
| **min Face interpolation weight** | **0.0117811599686** | **0.0117811599686** | **✓ 逐位** |
| **min Face volume ratio** | **0.0119216103667** | **0.0119216103667** | **✓ 逐位** |
| 低插值权面 (<0.05) | 114 | 106 | ✗ |

**两项独立判据的最值同时逐位相同、而其余全部不同** → 排除「整段复制」。

**推断（标注：未证）**：最差的那个面是**「形状决定」的、对 `maxh` 不敏感** ——
最可能来自**固定的 STL 表面三角形**（表面三角不变，贴表面单元的局部形状被它钉死），
或**修复自身产出的形状**。若成立，则**任何 `maxh` 调整都无法改善这几条最差面** ——
与「加分辨率无用（585→494）」互为印证。
**验证途径**：在 WSL 的 case 里定位该面并跨两套网格比对（需 `constant/polyMesh/owner`+`neighbour`）。

## 四、影响与处置（区分来源）

- 【源码有据】判据不中止求解 → **低权面本身是软症状，不是硬威胁**。
- 【源码有据】硬威胁更可能是 **585 个 `det<0.001` 单元**。
- 【文档/社区】**根治在网格侧**（修复表面退化三角 / 光顺 / 局部重剖分；`snappyHexMesh` 的 `minWeight`）。
  求解器侧只能**缓解**：`fvSchemes` 用 `Gauss linear limited/corrected`；`fvSolution` 提高
  `nNonOrthogonalCorrectors` / `nSweeps`。
  ⚠️ 本树**无 finiteVolume 模块**，solver 侧机制按文档/常识标注，**未逐行引用**。

## 六、给 T-004（诊断求解）的判读提示

1. **先确认跑的是哪套网格**：maxh=1.0 修复 → 预期 **114** 低权面；maxh=0.4 修复 → **106**。
   混淆会误导判读。本文 §二 已证两版**最差值相同**，但**计数不同**，仍须对齐。
2. **若发散**：先看 residual 是否在鼻腔狭窄/转弯等几何突变区前几步骤然抬升（低权面常聚于此）；
   再把 `lowWeightFaces` set 放进 case 的 `constant/polyMesh/sets` 反查 `U`/`p` 残差是否在那附近异常。
3. **对照看 585 差单元区是否同步发散**：若是 ⇒ 硬威胁在 determinant 而非低权重，
   **优先网格修复那批单元**。
4. **若收敛但局部残差偏高**：属预期（低权重只降精度不致命），可 `limited`/`corrected` +
   提高 `nNonOrthogonalCorrectors` 缓解，但仍建议回头做网格修复根治。
