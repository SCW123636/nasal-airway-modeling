## ★ 三个静默失败坑（本次全部实测定位并修复；均为"判据合法但与事实不符"类）

### 坑 1：命名 shell 变量在 Windows→WSL 途中被吃空
- 现象：`for f in CASE/*; do ln -s "$f" SCRATCH/; done` 到达 WSL bash 时 `$f` 为**空**，每次迭代报 `failed to create symbolic link 'SCRATCH/' -> ''`。`$?`/`$0` 存活，`$f`/`$p` 等命名变量一律被吃（与既有"shell 变量被 Git Bash 吃"同族的新变种，本次第 5 次踩到）。
- 修复：全部命令改**无变量写法**（字面路径 + glob + `ln -s SRC... DEST/`）。

### 坑 2：提取器 legacy dat 回退 → 静默降级 Float32
- 现象：本 case controlDict 只定义逐 patch 函数对象（flowInL/flowInR/flowOut/pressureInL/pressureInR/pressureOut）；`postProcessing/flowIn/` 与 `pressureIn/` 是**重启前配置的残留目录，dat 文件为空**。提取器 `dat_value()` 的 legacy 回退读到空文件 → 返回 None → 静默回退 VTK Float32 压力。
- 修复：在暂存目录按提取器文档化的 `flow_<patch>` / `pressure_<patch>` 命名提供**逐 patch 双精度副本**（仅改名，值不动）。主结果 `delta_p_pa.source = function_object_dat`（双精度）。

### 坑 3：b15 网格 wall patch 类型不是 `wall` → WSS 函数对象静默写全零场
- 现象：第一次提取输出 `wall_shear_force_n = 0.0`，**无任何警告**。查因：`constant/polyMesh/boundary` 里四个 patch 全是 `type patch`（gmshToFoam 默认），`wall` patch 也是 `patch` → `wallShearStress` 函数对象找不到 wall 型 patch → 写 `internalField uniform (0 0 0)`，dat 只有表头。
- **A/B 对照（单变量）**：复制 case 到 `t042_b15_wssfix`，只把 wall patch 改成 `type wall`，checkMesh 计数逐项一致（points 229033 / faces 2378797 / cells 1161194 / patches 4，Failed 2 不变）→ 同网格同场重跑 postProcess → WSS 非零（dat 出现 min/max 行，场 86 822 个非零矢量）。**根因确证 = patch 类型，与网格几何/求解无关。**
- 修复（两层）：
  1. 本卡：在 patch 类型修正后的副本上重取指标；**原 case 未被改动**（修正只发生在副本）。
  2. 共享库 `work/lib/extract_cfd_metrics.py`：补「全零判据」——WSS 数组存在但在非零面积 wall patch 上积分**恰为 0** → 报 `not_computed` + 原因 + warning，**不再报 0.0**（Float32 下真实流场不可能整 patch 恰零）。TDD：先红后绿，新增 2 个测试，**7/7 全过**；用修复后库重取 b15，输出与修复前**逐位一致**（非零路径不受影响）。

## R 低于 ISCOANA 参考 6.1× 的解释（诚实边界，不迁就）

三个因素方向相同（都使实测 R 偏低），但**不一定补足 6× 差距**，故如实记录为开放项：
1. **层流假设**：鼻瓣峰值 4.57 m/s、当地 Re≈1.8e3（D≈6mm）已进入过渡区，层流求解低估局部损失 → 真实 R 应**高于** 0.041。
2. **出口切面偏宽**：487.7 mm² 超解剖后鼻孔文献带（297–362），域因此偏短 → 低估阻力（待与开口定位 v2 报告核对）。
3. **病理方向**：若该例主诉为 ENS 向（干燥/结痂/烧灼，T-043 卡记载 7/7 源一致），低阻力与病理方向一致 —— 但本卡**不宣称诊断一致性**，仅记录数值与参考的差异。
