## 1. 一句话结论

**k-ω SST 在 b15 扩展域网格上无法稳定运行**——两次壁面函数配置均在起步阶段 ω 场发散到 1e19~1e29
并触发（或逼近）FPE；**根因已量化坐实**：壁面函数 ω_wall ∝ 1/y²，而该网格存在**近壁距离≈0 的退化单元**
（y₁ 分布的 p01/p05 分位 = 0.0 mm）。关掉壁面函数后 k/ω 输运本身可跑，但该网格 y+ 中位 7.7 / p95 28
（**非低-Re 区**）→ 无壁面函数的做法**物理上不成立**，故**本轮不产出任何可用于对照的湍流场**。

对 T-049「湍流是下一个可能改变形态的量」的回答修正为：**不是"湍流不影响形态"，而是"该患者网格上湍流暂不可达"**——
差别在于这是网格前置条件问题，不是物理结论。

**根因锁定在壁面函数，而非 k/ω 输运方程本身**。

## 4. 根因量化（决定性证据）

壁面函数 ω 壁面值按 ω_wall ≈ 6ν/(β₁ y²) 计算（β₁=0.075、ν=1.5e-5 m²/s）：

| 近壁距离 y | ω_wall |
|---|---|
| 0.5 mm（正常第一层） | ~4.8e5 |
| 1 µm | ~1.2e9 |
| 1 nm | ~1.2e15 |

实测 ω 爆到 **1e19~1e29**，对应 y 趋近于 0 —— 与 y₁ 分布 **p01 = p05 = 0.0 mm**
（`yplus_estimate_ext.json`，近壁单元中心到壁面最近距离）**量级自洽**。
网格侧佐证：T-054 扩展域网格有 **466 个 det<0.001 单元**（sliver 类退化单元）。

**为什么层流不受影响**：层流不消费壁面距离与壁面函数，故 T-054（同网格，M2 四判据全过、
不平衡 3.49e-8）完全正常 → 该缺陷只在启用湍流壁面处理时暴露。

## 7. 新坑记录（本轮）

1. **`pkill -f simpleFoam` 自杀**：`-f` 匹配完整命令行，执行它的 bash 自身命令行里就含 "simpleFoam"
   → 把自己也杀了（exit 15）。改用 **`pkill -x simpleFoam`**（精确进程名）。
2. **共享库 `flow_streamlines.PATCH_FILES` 是短域常量** `("nostril_L","nostril_R","nasopharynx_outlet","wall")`，
   扩展域出口是 `oropharynx_truncation_outlet` → `extract_field` 直接 FileNotFoundError。
   本轮就地收窄为 `("wall",)` 绕过；**治本参数化待立卡**（影响所有扩展域后处理脚本）。
3. **`foamToVTK -ascii` 输出目录名用 index 而非时间值**：产出 `VTK/<case>_0/`（index='0'），
   真实时间写在 vtu 注释 `time='600'` 里 → 按目录名取时间会取错。
4. **共享库 VTK 解析器只吃 ASCII**：T-054 原产 VTK 是 binary（foamToVTK 默认），
   必须在**只读源 case 的副本**上重跑 `-ascii` 才能用既有后处理链。
